## 🔄 1) 5초마다 상태 갱신

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| 시작 | 화면 뼈대 접속 | HTML 뼈대만 받고, **데이터는 API가 채움** |
| ① | 관리자 로그인 확인 | 세션이 지금도 존재하는 관리자를 가리키는지 확인 |
| ② | **잠깐 보관한 응답**이 있으면 그대로 | 탭이 여러 개여도 같은 조회를 나눠 쓰도록 **3초** 보관 |
| ③ | 만료된 잠금 정리 | 정해진 간격마다 "풀릴 시간이 지난 잠금"을 풀어줌 (별도 타이머 없음) |
| ④ | **조회 17개를 동시에** | 로그인 시도·잠긴 IP·회원·게시글·이벤트·사건·AI 경보… |
| ⑤ | 시도 기록에 접속 위치 붙이기 | 4단원 |
| ⑥ | 관리자 계정 카드는 **super_admin에게만** | 권한이 없으면 응답에 **키 자체가 없음** |
| ⑦ | JSON으로 응답하고 보관 | |
| ⑧ | 처리 버튼(POST) 후 보관 응답을 **비움** | 방금 누른 결과가 오래된 값에 가려지지 않게 |

<aside>
⚡ **왜 "동시에" 조회하나요?**
조회 하나가 DB까지 갔다 오는 데 대략 0.15~0.5초가 걸립니다. 17개를 **하나씩** 기다리면 2~3초가 걸리지만, **동시에** 보내면 "가장 느린 하나"만큼만 기다립니다(실측 약 5배 개선). 특히 서버리스 환경(Vercel)은 요청마다 연결을 새로 맺어야 해서 체감이 컸습니다.
</aside>

<aside>
🙈 **권한이 없는 카드는 "숨기는" 게 아니라 "아예 안 보냅니다."**
화면에서 숨기면 개발자 도구로 데이터가 보일 수 있습니다. 그래서 권한이 없으면 서버 응답에 **그 데이터 자체를 넣지 않습니다.**
</aside>

## 🔓 2) "즉시 해제" 버튼

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 권한 확인 + 입력 확인 | `unlock_ip` 권한이 있는 관리자만 도달 |
| ② | 지금 정말 잠긴 IP인가? | 활성 잠금 목록에 없으면 아무것도 안 함 |
| ③ | **영구 잠금**이면 거부 | "영구 해제"(super_admin 전용)로만 풀 수 있음 (409) |
| ④ | 해제 + CRITICAL 이벤트 정리 | 행은 **지우지 않고** `active=False`로만 바꿔 이력을 남김 |

<aside>
📌 **사건은 닫지 않습니다.**
잠금을 푸는 것(접속 차단을 거두는 일)과 사건을 닫는 것(관리자가 조사를 마쳤다는 판단)은 **별개**입니다. 사건은 "해결" 버튼으로만 닫힙니다(9단원).
</aside>

## 🧪 예시로 보기

관리자가 잠긴 IP 목록에서 `1.2.3.4`(5분 잠금, 남은 3분 12초)를 보고 **"즉시 해제"** 클릭
→ 다음 폴링(5초 이내)에 목록에서 사라지고 → 회원 `/login`에서 그 IP로 **즉시 재시도 가능**해집니다.

## 🖥️ 직접 해보기

- [ ] 5단원의 방법대로 브루트포스를 일으켜 IP를 잠근다
- [ ] 관리자로 로그인해 "잠긴 IP" 카드에서 방금 잠긴 IP를 확인한다
- [ ] "즉시 해제"를 눌러 몇 초 안에 목록에서 사라지는지 확인한다
- [ ] `/login`에서 그 IP로 다시 시도해 통과하는지 확인한다

> 대시보드에는 실제 접속 로그(IP·위치 등 민감 정보)가 나오므로 스크린샷을 저장소에 넣지 않았습니다.

## 📖 용어 사전

<details>
<summary><b>폴링(Polling)</b></summary>

서버가 알려주는(push) 방식이 아니라, 브라우저가 주기적으로 "새 소식 있어?" 하고 계속 물어보는 방식입니다.

<details>
<summary><b>JSON</b></summary>

파이썬의 딕셔너리와 거의 똑같이 생긴, 서버와 브라우저가 데이터를 주고받는 표준 형식입니다.
</details>
