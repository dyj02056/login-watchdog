# 미니 관제창 (크롬 확장, 항상 위 PiP)

> 요약은 [루트 README](../README.md)에 있습니다. 이 문서는 확장의 사용법과 동작 방식을 자세히 설명합니다.

관리자 대시보드는 여는 데 시간이 걸리고, 다른 일을 하면서 계속 띄워 두기도 어렵습니다. **미니 관제창**은 크롬 확장프로그램입니다. 화면 한쪽에 **항상 위에 떠 있는 작은 창**(약 340×400)을 띄우고 **"지금(최근 30분) 공격이 들어오고 있는지"만** 보여 줍니다. 유튜브의 PiP(화면 속 화면) 창과 같은 기술을 씁니다. 자세한 내용이 필요하면 창 아래 버튼을 눌러 크롬에서 관리자 대시보드를 엽니다.

- 소스: [extension/](../extension) (빌드 없이 순수 자바스크립트, Manifest V3)
- 서버 쪽: `GET /api/pip/check` ([routes/admin/status.py](../routes/admin/status.py)), 조회 함수 2개 ([db/security_events.py](../db/security_events.py))
- 필요한 것: 크롬 116 이상(Document Picture-in-Picture 지원), 관리자 계정

## 1. 화면

| 상태 | 보이는 것 |
|---|---|
| **로그인** | 아이디·비밀번호 입력. 크롬에서 이미 관리자로 로그인해 두었으면 이 화면 없이 바로 관제 화면이 뜹니다 |
| **정상** 🟢 | "정상 — 최근 30분 공격 없음", 마지막 확인 시각 |
| **MEDIUM** 🟡 / **HIGH** 🟠 / **CRITICAL** 🔴 | "HIGH 공격 탐지 중 · 마지막 공격 10:13", 최근 30분 공격 수(전체·CRITICAL·HIGH), 1분 단위 그래프, 최근 공격 5건(등급·시각·공격 종류·출발지 IP). 새로 들어온 줄은 잠깐 깜빡입니다 |
| **서버 연결 안 됨** | 원인별 안내 문구와 [다시 시도] 버튼(아래 [7. 문제 해결](#7-문제-해결)) |

- 등급은 서버의 위험등급(`CRITICAL`·`HIGH`·`MEDIUM`, [guide22](beginner-guide/guide22_security_grading.md))을 그대로 씁니다.
- 맨 위 띠의 색과 오른쪽 위 글자가 지금 등급입니다. **최근 30분** 동안 들어온 공격 중 가장 높은 등급이고, 공격이 없으면 "정상"입니다.
- 처리하지 않은 예전 공격(미해결)은 미니 창에서 보지 않습니다. 미해결 공격은 관리자 대시보드에서 처리합니다. 공격이 멈추고 30분이 지나면 미니 창은 저절로 "정상"으로 돌아갑니다.
- 그래프는 막대 하나가 1분이고 맨 오른쪽이 지금입니다. 막대 색은 그 1분 동안 가장 높은 등급입니다.
- 맨 아래 **[관리자 대시보드로 이동]**을 누르면 이미 열린 대시보드 탭으로 이동하고, 없으면 새 탭으로 `/admin/dashboard`를 엽니다.
- 공격 종류는 대시보드와 같은 한국어 이름으로 보여 줍니다(`NET_BLOCKED` → 네트워크 차단, `NET_SYN_FLOOD` → SYN 플러드 등).

## 2. 설치 (처음 한 번)

1. 크롬 주소창에 `chrome://extensions`를 입력하고 Enter를 누릅니다.
2. 오른쪽 위 **개발자 모드** 스위치를 켭니다.
3. 왼쪽 위 **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 저장소의 `extension` 폴더를 고르고 **폴더 선택**을 누릅니다.
5. 목록에 "Login Watchdog 미니 관제창"이 생기면 설치 완료입니다.
6. 주소창 오른쪽 퍼즐 모양(🧩)을 누르고, 이 확장 옆의 📌 핀을 눌러 툴바에 고정해 두면 편합니다.

코드를 고쳤거나 저장소를 새로 받았으면 `chrome://extensions`에서 이 확장의 **↻(새로고침)** 버튼을 눌러야 반영됩니다.

## 3. 설정 (처음 한 번)

설치하면 설정 화면이 자동으로 열립니다. 안 열리면 확장 아이콘을 오른쪽 클릭한 뒤 **옵션**을 누릅니다.

1. **관리자 대시보드 주소**에 앞부분만 적습니다. 예: `http://localhost:5000`, `https://login-watchdog.vercel.app`
2. **새 공격 확인 간격**은 기본 10초를 권장합니다(5~120초). 미니 창이 열려 있을 때의 간격입니다.
3. **저장**을 누르면 크롬이 "이 사이트의 데이터 읽기·변경" 권한을 묻습니다. **허용**해야 미니 창이 크롬의 로그인 상태를 같이 쓸 수 있습니다.
   - 권한은 적은 주소 하나에만 받습니다. 처음부터 모든 사이트 권한을 받지 않습니다.

## 4. 사용

1. 툴바의 확장 아이콘(청록색 동그라미)을 누릅니다. 단축키는 `Alt+Shift+W`입니다.
2. 왼쪽 끝에 작은 **고정 탭**이 열립니다. 그 화면의 **[미니 창 열기]**를 누릅니다.
3. 항상 위에 떠 있는 미니 창이 뜨고, 원래 보던 탭으로 자동으로 돌아갑니다.
4. 미니 창이 오른쪽 아래에 뜨면 **창 윗부분을 끌어 왼쪽 위로** 옮겨 두세요.
5. 로그인 화면이 나오면 관리자 아이디·비밀번호로 로그인합니다. 미니 창에서 로그인하면 크롬 탭의 대시보드도 로그인된 상태가 됩니다.

> ⚠ **고정 탭을 닫으면 미니 창도 같이 닫힙니다.** 고정 탭은 그대로 두세요. 닫았으면 아이콘을 다시 누르면 됩니다.

**미니 창을 닫아 두었을 때**

- 30초마다 새 공격만 확인합니다. 새 공격이 오면 확장 아이콘에 **숫자 배지**가 붙습니다.
- HIGH 이상이면 화면 오른쪽 아래에 **윈도우 알림**이 뜹니다.
- 알림을 누르면 고정 탭이 열리고, **[미니 창 열기]**로 다시 띄우면 됩니다.

## 5. 동작 방식

### 구성 요소

| 구성 요소 | 파일 | 하는 일 |
|---|---|---|
| 백그라운드(서비스 워커) | `background.js` | 아이콘·단축키를 누르면 고정 탭을 엽니다. 미니 창이 닫혀 있으면 30초마다 확인해 배지·알림을 띄웁니다. HTTPS 로그인용 Referer 규칙을 겁니다 |
| 고정 탭(호스트) | `host.html` · `host.js` | 버튼으로 PiP 창을 열고 붙잡아 둡니다. 창 안의 화면과 10초 확인을 맡습니다 |
| PiP 창 화면 | `pip/view.js` · `pip/pip.css` | 로그인·관제·연결 실패 화면을 그립니다 |
| 확인 흐름 | `lib/monitor.js` | 처음 한 번 집계, 그 뒤로는 가벼운 확인만 합니다. 등급 계산, 401·404 처리 |
| 계산 | `lib/core.js` | 최근 30분 등급·건수, 1분 그래프 칸, 이벤트 합치기, 한국어 공격 이름, 배지 |
| 서버 요청 | `lib/api.js` | 세션 확인, 로그인, 확인 API, 집계, 대시보드 탭 열기 |
| 설정 | `options.html` · `options.js` | 대시보드 주소·확인 간격을 저장하고, 그 주소 하나의 권한을 요청합니다 |

**왜 고정 탭이 필요한가.** 크롬은 PiP 창을 사용자가 직접 누른 버튼에서만 열게 합니다(광고 팝업 방지). 또 PiP 창은 그것을 연 문서가 닫히면 같이 닫힙니다. 확장 아이콘을 누르면 뜨는 팝업은 다른 곳을 클릭하는 순간 닫혀서 PiP를 붙잡아 둘 수 없습니다. 그래서 고정 탭에서 엽니다. 같은 이유로 공격이 와도 PiP 창이 **저절로 열리지는 않습니다**.

**타이머는 PiP 창의 것을 씁니다.** 고정 탭은 대부분 뒤에 숨어 있어서 크롬이 그 탭의 타이머를 1분에 한 번으로 늦출 수 있습니다. 화면에 보이는 PiP 창의 타이머는 늦추지 않습니다.

### 서버에 묻는 순서 (Supabase 무료 플랜 부담 줄이기)

| 언제 | 요청 | Supabase 조회 |
|---|---|---|
| 미니 창을 열 때 한 번 | `/api/pip/check`(기준점) + `/api/stats` | 약 20번(기존 대시보드 집계와 같음) |
| 그 뒤 10초마다 | `/api/spa/session` + `/api/pip/check?after=<마지막 id>` | 2번(로그인 세션 확인 1 + 새 이벤트 확인 1), 응답은 대부분 빈 값 |
| 미니 창이 닫혀 있을 때 30초마다 | 위와 같음 | 2번 |

- 새 공격 목록은 확인 API 응답에 이미 들어 있습니다. 그래서 **공격이 들어와도 집계(`/api/stats`)를 다시 부르지 않습니다**.
- 30분이 지난 공격은 서버에 묻지 않고 화면에서 빠집니다.
- 미니 창이 열려 있는 동안 백그라운드는 확인을 쉽니다. 같은 확인을 두 군데서 하지 않기 위해서입니다.

### `GET /api/pip/check`

| 항목 | 내용 |
|---|---|
| 권한 | `@login_required`(관리자 세션). 조회만 해서 `/api/stats`와 같은 수준입니다 |
| `after` 없음 | 기준점만 돌려줍니다: `{"latest_id": 812, "new": [], "more": false}` (표가 비어 있으면 `latest_id: null`) |
| `after=<id>` | 그 id보다 뒤에 기록된 `security_events`를 오래된 순으로 최대 20건 돌려줍니다. 각 건의 칸: `id, severity, event_type, ip_address, path, count, action, detected_at` |
| 넘칠 때 | 21건 이상이면 20건만 주고 `more: true`. 확장은 1초 뒤 마지막 id부터 이어 받습니다 |
| 반복 접근 감시 | 10초마다 같은 주소를 부르므로, 대시보드 폴링 API처럼 반복 접근·매크로 감시와 전역 요청 한도에서 뺐습니다(`PAGE_ACCESS_EXCLUDED_ENDPOINTS`) |

제외 목록은 원래 `helpers/hooks.py`에 있습니다. 그 파일은 수정하지 않기로 한 파일([AGENTS.md](../AGENTS.md))이라, `routes/admin/status.py`에서 같은 집합에 `admin.api_pip_check`를 추가합니다. 요청 한도와 감시 훅이 같은 집합 객체를 참조하므로 효과는 같습니다.

### 로그인과 보안

- **비밀번호를 저장하지 않습니다.** 로그인 상태는 서버의 세션 쿠키가 전부입니다.
  - 확장은 대시보드 주소 권한을 받아 두었기 때문에, 확장이 보내는 요청에도 크롬의 그 사이트 쿠키가 실립니다. 그래서 크롬 탭과 미니 창이 로그인 상태를 같이 씁니다.
- **로그인은 기존 관리자 로그인과 똑같은 경로**(`POST /admin/login`, CSRF 토큰, 비워 둔 허니팟 칸)로 보냅니다.
  - IP 잠금·관리자 계정 잠금·허니팟 검사가 그대로 적용됩니다([guide38](beginner-guide/guide38_admin_account_lockout.md)).
- **로그아웃 상태에서는 확인 API를 부르지 않습니다.** 세션 없이 `/api/`를 부르면 서버가 "미인증 접근"으로 기록하고, 반복되면 경보를 보내기 때문입니다.
  - 그래서 매번 DB를 조회하지 않는 `/api/spa/session`으로 로그인 여부부터 봅니다.
  - 401이 오면 확인을 멈추고 로그인 화면으로 바꿉니다.
- **서버에서 받은 값은 화면에 글자로만 넣습니다**(`textContent`). IP 칸 등에 이상한 글자가 와도 화면 코드로 실행되지 않습니다.
- **HTTPS 배포에서의 로그인**: Flask-WTF는 HTTPS 요청의 Referer가 같은 사이트인지 검사합니다.
  - 확장은 `declarativeNetRequest` 규칙으로 **자기 요청에만** Referer를 대시보드 주소로 맞춥니다.
  - 그래도 막히면 미니 창에 **"크롬 탭에서 로그인하기"** 버튼이 나옵니다. 그 탭에서 로그인하면 미니 창이 5초 안에 알아챕니다.

## 6. 테스트

```bash
pytest tests/test_pip_check.py -q
node --test extension/test/core.test.mjs extension/test/monitor.test.mjs
```

- **`tests/test_pip_check.py`** (8개, monkeypatch로 DB 없이):
  - 로그인 안 하면 401이고 조회도 하지 않음
  - 기준점 / 빈 표
  - 새 이벤트 없음 / 있음
  - 21건 이상 몰리면 나눠 받기
  - 잘못된 `after`
  - 반복 접근 감시에서 제외
- **`extension/test/`** (25개, Node 내장 테스트, 크롬 없이):
  - 최근 30분 등급·건수(어젯밤 공격은 정상), 1분 그래프 칸, 알림 대상(HIGH 이상), 배지, 주소 다듬기
  - 확인 흐름: 집계는 처음 한 번뿐, 공격이 멈추고 30분 뒤 정상, 로그아웃이면 확인 안 함, 401·404·500 처리
- GitHub Actions(`tests.yml`)는 pytest만 돌립니다. JS 테스트는 직접 실행해야 합니다.

## 7. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| "이 서버에는 아직 미니 창 기능(/api/pip/check)이 없습니다" | 서버가 이 기능이 들어가기 전 코드입니다(404). 로컬에서만 고치고 배포하지 않은 경우 | 서버를 최신 코드로 배포합니다(Vercel은 main에 푸시하면 자동 배포). 배포 뒤 [다시 시도] |
| "서버에 연결하지 못했습니다. 주소 설정과 인터넷 연결을 확인해 주세요" | 주소가 틀렸거나, 서버가 꺼져 있거나, 권한을 허용하지 않음 | 설정에서 주소를 다시 저장하고 권한을 **허용**합니다. 로컬이면 `python app.py`가 켜져 있는지 확인합니다 |
| "서버가 오류로 응답했습니다(HTTP 500)" | 서버 쪽 오류 | 서버 로그를 확인합니다. 15초마다 자동으로 다시 시도합니다 |
| 로그인 후 "크롬 탭에서 로그인하기"가 보임 | HTTPS 서버의 Referer 검사에 막힘 | 버튼으로 연 탭에서 로그인하면 미니 창도 로그인 상태로 바뀝니다 |
| 미니 창이 갑자기 닫힘 | 고정 탭을 닫았거나 새로고침함 | 아이콘을 다시 누르고 [미니 창 열기] |
| [미니 창 열기]가 눌리지 않거나 지원하지 않는다고 나옴 | 크롬 116 미만 | 크롬을 업데이트합니다 |
| 공격이 있었는데 미니 창은 정상 | 공격이 30분보다 전에 있었음 | 의도된 동작입니다. 지난 공격·미해결 공격은 관리자 대시보드에서 봅니다 |

## 8. 제한사항

- **처음 위치를 코드로 정할 수 없습니다.** 크롬 기본값(오른쪽 아래)으로 뜰 수 있어서 한 번 끌어 옮겨야 합니다.
- **창 크기를 저절로 바꿀 수 없습니다.** 크롬은 PiP 창 크기 변경도 사용자 클릭이 있을 때만 허락해서, 정상일 때와 공격 중일 때 같은 크기를 씁니다.
