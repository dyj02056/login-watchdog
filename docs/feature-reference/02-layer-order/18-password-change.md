# 18. 비밀번호 변경 + 다른 기기 로그인 해제

<aside>
🎯 **한 줄 요약**
비밀번호를 바꾸면 **지금 쓰고 있는 기기만 남기고, 다른 모든 기기의 로그인이 끊깁니다.** 비밀번호만 바꾸고 이미 로그인된 세션을 그대로 두면, 세션을 훔친 사람은 계속 로그인 상태로 남기 때문입니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [18-password-change.html](18-password-change.html)
> 📚 **계층**: Layer 5-A. 확장 기능 — Layer 1(회원 화면)의 기능이지만 Layer 2(로그인 실패 판정)와 연결됩니다

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 현관 **도어락 번호를 바꾸면** 예전 번호를 아는 사람은 못 들어옴 | 비밀번호 변경 |
| 그런데 **이미 안에 들어와 있는 사람**은 그대로 있음 → 모두 내보내야 함 | 다른 기기의 세션 해제 |
| 출입증에 찍힌 **"발급 차수"**가 다르면 무효 | 세션 세대 번호 |

---

## 🔄 비밀번호가 바뀌는 순서

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 봇 · 계정 잠금 확인 | 걸리면 세션을 정리하고 돌려보냄 |
| ② | **새 비밀번호 형식** 검사 | 길이 8자 이상 · 확인칸 일치 · 현재와 다름. **실패 횟수에는 넣지 않음** (입력 실수일 뿐이라) |
| ③ | **현재 비밀번호 확인** | 틀리면 **로그인 실패와 똑같이** 기록·잠금 |
| ④ | 새 해시 저장 + **세션 세대 번호 +1** | 이 기기 세션에만 새 번호를 적어 이 기기는 유지 |
| ⑤ | **변경 알림 메일** | 본인이 한 일이 아니면 바로 알 수 있게 |

<aside>
🧱 **왜 현재 비밀번호 틀림을 "로그인 실패"로 셀까요?**
그러지 않으면 이 화면이 **"잠금 없이 비밀번호를 무한히 맞춰보는 우회로"** 가 됩니다. 세션만 훔친 사람이 이 화면에서 비밀번호를 추측할 수 있게 되기 때문입니다.
</aside>

---

## 🪪 다른 기기는 어떻게 끊길까요?

```
로그인할 때:  세션에 "내 번호 = 0" 기록
비밀번호 변경: DB 번호 0 → 1   /   변경한 기기 세션 → 1
다른 기기가 다음 요청:  세션 0 ≠ DB 1  →  로그아웃 + 안내
```

회원 화면 요청마다 **회원 문지기**가 세션의 번호와 DB 번호를 비교합니다. 다르면(또는 계정이 삭제되어 번호를 못 찾으면) 회원 세션만 지우고 로그인 화면으로 보냅니다.

### 예시 (`wdprod01`)
| 단계 | DB 번호 | 기기 A | 기기 B |
|---|:-:|:-:|:-:|
| 둘 다 로그인 | 0 | 0 | 0 |
| A에서 비밀번호 변경 | **1** | **1** | 0 |
| B가 다음 요청 | 1 | 1 | 0 ≠ 1 → **로그아웃** |
| 되돌리려고 다시 변경 | 2 | 2 | – |

<aside>
⚙️ **동시에 바꿔도 안전한 이유 — 조건부 UPDATE**
번호는 "**읽은 값 그대로일 때만**" 올립니다. 두 기기에서 거의 동시에 바꾸는 드문 경우에도 번호가 한 번 덜 올라가 옛 세션이 살아남는 일이 없도록, 경쟁에서 지면 **다시 읽어서 한 번 더** 시도합니다(최대 3번).
</aside>

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 비밀번호 변경 처리 | `routes/member.py` | `member_password_submit()` |
| 틀렸을 때 잠금 판정 | `routes/member.py` | `_lock_if_suspicious()` |
| 로그인 시 번호 저장 | `routes/auth.py` | `login_submit()` |
| 요청마다 번호 비교 | `helpers/auth.py` | `member_login_required()` |
| 해시 저장 + 번호 증가 | `db/users.py` | `update_user_password()`, `get_user_session_version()` |
| 변경 알림 메일 | `notify/mailer.py` | `send_password_changed_notice()` |

## 🖥️ 직접 해보기

- [ ] 두 브라우저(일반 창 + 시크릿 창)에서 같은 계정으로 로그인한다

- [ ] 다른 쪽에서 아무 회원 화면으로 이동 → 로그인 화면으로 이동하며 안내가 뜨는지 확인한다
- [ ] 가입 이메일에서 "비밀번호가 변경되었습니다" 메일을 확인한다

## 📖 용어 사전

<details>
<summary><b>세션 세대 번호(`users.session_version`)</b></summary>

비밀번호를 바꿀 때마다 1씩 올라가는 숫자입니다. 세션에 적힌 번호가 다르면 그 세션은 무효입니다.
</details>

## ⚠️ 알아둘 한계

- 영구 잠금이 걸릴 때는 **이미 로그인된 세션을 끊지 않습니다.**
- 회원 화면 요청마다 **DB 조회가 1회 늘어납니다.**
- 비밀번호를 **잊었을 때** 메일로 재설정하는 기능은 이 단원 시점에는 없었고, 이후 24단원(비밀번호 찾기)에서 추가되었습니다.
