# 23. 이메일 인증 + 이메일 변경 보호

<aside>
🎯 **한 줄 요약**
비밀번호 찾기(24단원)는 "계정을 되찾는 메일"이라 그 메일이 가는 주소가 **확실히 본인 것**이어야 합니다. 그래서 **가입 이메일을 인증**하고, **이메일 변경은 "현재 비밀번호 + 새 주소로 보낸 확인 링크"** 를 거치게 했습니다.
</aside>

> 📚 **계층**: Layer 5-B. 확장 기능 — Layer 1(화면) + 서비스(`services/`) + 데이터

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 주소지가 **진짜 내 집인지** 확인하는 우편 (확인 번호가 적힌 엽서) | 인증 메일 링크 |
| 엽서를 **한 번만** 쓸 수 있는 번호표 | 1회용 토큰 |
| 주소를 바꾸면 **옛 주소로도 "바뀌었습니다" 통지** | 변경 알림 메일 |

<aside>
⚠️ **왜 이메일 변경이 위험했나요?**
예전에는 로그인 세션만 있으면 **비밀번호 확인 없이** 이메일을 바꿀 수 있었습니다.
**세션 탈취 → 이메일을 내 주소로 변경 → 비밀번호 재설정 → 계정 탈취**가 가능했습니다.
</aside>

---

## 📧 이메일 상태 3가지

| 상태 | 의미 |
|---|---|
| `UNKNOWN` | **미인증** (기존 회원은 모두 이 상태에서 시작 — 확인된 적 없는 주소를 확인된 것처럼 다루지 않기 위해) |
| `VERIFIED` | **인증됨** |
| `UNDELIVERABLE` | **반송** (메일 서버가 수신자를 영구 거부) |

---

## ✅ 1) 가입 이메일 인증

가입하면 가입 이메일로 **인증 링크(15분, 1회용)** 가 갑니다. 가입·로그인은 **인증 없이도** 바로 됩니다.

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 이미 인증됐나? · **쿨다운 60초** · **하루 5회** | 너무 자주·많이는 거절 |
| ② | 토큰을 만들고 **해시만 저장** | 링크는 Host 헤더가 아니라 `PUBLIC_BASE_URL`로만 |
| ③ | 메일 발송 | 못 보냈으면 **토큰 취소**, 수신자 영구 거부면 `UNDELIVERABLE` 표시 |

---

## 🔗 2) 링크로 확인 — GET은 화면만, POST에서 소비

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| 링크 열기 | **GET** → 확인 화면만 | 토큰을 **소비하지 않음** (메일 보안 스캐너가 먼저 열어도 괜찮게) |
| ① | 확인 버튼 **POST** | IP당 분당 한도가 따로 걸림 |
| ② | **1회만 소비** | 조건부 UPDATE — 같은 링크를 두 번 누르면 두 번째는 "이미 사용된 링크" |
| ③ | 인증 링크면 `VERIFIED` | 메일을 보낸 뒤 이메일을 바꿨다면 옛 주소로 간 링크는 **무효(STALE)** |

<aside>
📱 **로그인을 요구하지 않는 이유**
메일은 휴대폰에서 여는 경우가 많고, **추측할 수 없는 토큰을 가진 사람이 곧 그 메일함의 주인**이기 때문입니다.
</aside>

---

## ✏️ 3) 이메일 변경 보호

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| 시작 | 프로필에서 변경 요청 | **현재 비밀번호**를 먼저 확인 (틀리면 로그인 실패와 똑같이 기록·잠금) |
| ① | **새 주소로 "확인 링크"만 발송** | 바로 바뀌지 않음 |
| ② | 다른 계정이 쓰는 주소여도 **화면 응답은 같음** | 그 주소로는 "이미 등록된 주소" 안내 메일만 감 |
| ③ | **링크를 눌러야 반영** + **기존 주소로 알림** | 그사이 다른 계정이 그 주소를 차지했다면 변경 안 함 |

### 공격자가 가진 것에 따라

| 공격자가 가진 것 | 결과 |
|---|---|
| **세션만** | 현재 비밀번호를 몰라 **막힘** |
| 세션 + 비밀번호 | 자기 주소로 확인은 되지만, **기존 주소로 변경 알림**이 가서 주인이 알아챔 |

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 인증 메일 보내기 | `services/email_verification.py` | `send_verification()` |

| 이메일 변경 요청 | `services/email_verification.py` | `request_email_change()` |
| 링크 확인·반영 | `services/email_verification.py` | `confirm()` |

| 이메일 변경 입구 | `routes/member.py` | `member_email_change_submit()` |
| 토큰 저장·1회 소비 | `db/email_tokens.py` | `create_email_token()`, `consume_email_token()` |
| 메일 | `notify/mailer.py` | `send_email_verification()`, `send_email_change_confirmation()`, `send_email_changed_notice()` |

## 🖥️ 직접 해보기

- [ ] 로컬에서 `MAIL_BACKEND=console`(터미널 출력) 또는 Mailpit으로 띄운다
- [ ] 회원 대시보드의 **"인증 메일 보내기"** → 터미널에 찍힌 링크 → **[인증]** 클릭
- [ ] 대시보드의 "이메일 인증이 필요합니다" 배너가 사라지는지 확인한다
- [ ] 관리자 대시보드 회원 목록에서 이메일 옆 **인증됨/반송** 배지를 확인한다
