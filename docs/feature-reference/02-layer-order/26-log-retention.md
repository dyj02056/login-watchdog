# 26. 로그 자동 정리 + 일별 요약

<aside>
🎯 **한 줄 요약**
페이지 접속·404·로그인 시도 같은 기록은 요청마다 한 줄씩 쌓입니다. 이 기록을 **하루 단위로 "건수만" 요약해 보관**하고, **보관 기간이 지난 원본은 매일 새벽에 자동으로 지웁니다.** 앱 코드가 아니라 **DB 안에서** 돌아갑니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [26-log-retention.html](26-log-retention.html)
> 📚 **계층**: Layer 5-B. 확장 기능 — 앱 코드 밖, **DB 안**(Supabase `pg_cron`)에서만 동작

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| CCTV 영상을 **매일 새벽에 "일일 보고서(건수)"로 요약**하고, 오래된 영상은 삭제 | 일별 요약 + 원본 정리 |
| 보고서를 **쓰기 전에는 영상을 지우지 않음** | 요약 전 기록은 절대 안 지움 |
| 새벽 3시에 자동으로 돌아가는 **청소 로봇** | `pg_cron` 예약 작업 |

<aside>
💡 **왜 필요한가요?**
평소에는 작아도, 여러 IP에서 공격이 몰리면 **하루 수십만 줄**이 쌓일 수 있습니다. 또 대시보드에 그래프를 넣으려면 오래된 날짜까지 **일정한 형태의 요약**이 필요합니다.
</aside>

---

## ⏰ 매일 새벽 3시 (한국 시간)에 일어나는 일

예약 작업 `daily-log-maintenance`가 **UTC 18시 = 한국 새벽 3시**에 실행됩니다.

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | **요약 먼저, 정리는 그다음** | 이 순서 덕분에 요약되지 않은 기록이 먼저 지워지는 일이 없음 |
| ② | 요약 안 한 날부터 **어제까지, 하루씩** 요약 | 마지막 요약일 다음 날부터. 밀린 날도 이 방식으로 채움 |
| ③ | 표 하나의 하루치를 **덮어쓰기**로 요약 | 여러 번 실행해도 결과가 같음 |
| ④ | 시간대별 건수 + 상세(IP 수·상위 경로·나라별) | 요약표에는 **건수만** 남음 |
| ⑤ | **삭제 기준 = min(보관 기간, 마지막 요약일 다음 날 0시)** | 요약 전 기록은 절대 안 지움 |
| ⑥ | **처리 전·대기 중인 것은 지우지 않음** | |
| ⑦ | 실제 삭제 | `dry_run`이면 건수만 셈 |
| ⑧ | 웹 요청으로는 **호출 불가** | 사이트·API 키로 못 부르게 막아 둠 |

### 얼마나 보관하나요?

| 기록 | 보관 기간 |
|---|---|
| 접속·시도 기록 (페이지 접근, 404, 가입·글·댓글 시도, API 접근) | **30일** |
| 끝난 메일 링크 (복구·이메일 인증) | **30일** |
| 로그인 기록, **처리 완료된** 보안 이벤트·사건·승인 요청 | **90일** |
| IP 위치 캐시 | 30일 |

<aside>
🛡️ **지우지 않는 것**
처리 **전**인 이벤트, **대기 중**인 링크, **잠금 이력**, **회원 정보**는 지우지 않습니다. 요약표에는 IP·아이디 자체가 남지 않고 **건수만** 남습니다.
</aside>

## 🗂️ 요약표 3개

| 표 | 담는 것 |
|---|---|
| `log_daily_summary` | **시간대별 건수** — (날짜, 시간, 표, 종류) → 건수 |
| `log_daily_breakdown` | **하루 상세** — 서로 다른 IP 수 · 로그인 실패에서 노린 아이디 수 · 많이 노린 주소 상위 5개 · 로그인 기록의 나라별 건수 |
| `log_summary_state` | **어디까지 요약했나** (한 줄짜리 표) |

---

## 📍 코드는 어디에 있나요? (모두 `docs/schema.sql`의 SQL 함수)

| 하는 일 | 함수 |
|---|---|
| 매일 할 일: 요약 → 정리 | `run_daily_log_maintenance()` |
| 요약 안 한 날 채우기 | `summarize_pending_log_days()` |
| 하루치 전체 요약 | `summarize_log_day()` |
| 표 하나의 하루치 요약 | `_summarize_log_source()` |
| 오래된 원본 삭제 | `cleanup_old_logs()`, `_delete_old_log_rows()` |
| 예약 | `cron.schedule('daily-log-maintenance', '0 18 * * *', ...)` |

## 🧪 예시로 보기

| 표 | 예 |
|---|---|
| `log_daily_summary` | (2026-10-07, 14시, `login_attempts`, `failure`) → **3** |
| `log_daily_breakdown` | (2026-10-07, `login_attempts`, `distinct_ips`) → **2** / (`country`, `South Korea`) → **4** |

## 🖥️ 직접 해보기 (Supabase SQL Editor)

```sql
select * from cleanup_old_logs(true) where deleted_rows > 0;   -- 지울 건수만 미리 보기(아무것도 안 지움)
select last_summarized_day from log_summary_state;              -- 어디까지 요약했나
select day, sum(count) from log_daily_summary
where source = 'login_attempts' and category = 'failure' group by day order by day;   -- 날짜별 로그인 실패
```

> 앱 화면에는 변화가 없습니다. 요약표는 앞으로 대시보드 시각화에 쓸 수 있습니다.

## 📖 용어 사전

<details>
<summary><b>pg_cron</b></summary>

Postgres(DB) 안에서 **정해진 시각에 SQL을 실행**하는 예약 작업 기능입니다. 앱 서버가 꺼져 있어도 DB가 스스로 실행합니다.
</details>

<details>
<summary><b>dry run</b></summary>

실제로 바꾸지 않고 **"하면 어떻게 되는지"만 미리 보는** 실행 방식입니다. 여기서는 지울 건수만 세어 줍니다.
</details>

## ⚠️ 알아둘 한계

- **지운 원본은 되돌릴 수 없습니다.** (무료 요금제에는 사용자가 복원할 백업이 없음) 30·90일보다 오래된 기간을 `daily_report.py --start/--end`로 보면 비어 나옵니다.
- 켜는 방법: `docs/migrations/guide44_log_retention.sql` 실행 후 `guide47_daily_log_summary.sql` 실행 (앱 코드와 무관해 언제 실행해도 됩니다).
