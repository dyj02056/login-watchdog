# 42단계 — IPv6는 /64 대역 단위로 세고 잠근다

[◀ 41단계](guide41_password_reset.md) · [전체 목차](beginner-guide.md)

> 지금까지 IP 잠금·IP 단위 탐지·요청 제한은 모두 **주소 하나**를 단위로 셌습니다. IPv4에서는 문제가 없지만, IPv6 사용자는 주소를 거의 공짜로 바꿀 수 있어서 이 방식이 통째로 우회됩니다. 요청 IP를 한 곳에서 "탐지·잠금 단위"로 정규화해 IPv6는 **/64 대역**을 한 단위로 보게 했습니다. DB 스키마 변경은 없습니다.

## 먼저 — 지금 운영에는 IPv6가 들어오지 않는다

작업 전에 확인한 사실입니다.

| 확인 | 결과 |
|---|---|
| 운영 DB의 IPv6 주소 (login_attempts 219건, admin_login_log 75건, page_access_attempts 1,375건, lockouts, security_events) | **0건** |
| `login-watchdog.vercel.app` DNS | IPv4(A 레코드)만 있고 **IPv6(AAAA)는 없음** — 방문자가 IPv6 망에 있어도 IPv4로 접속한다 |

그래서 이 단계는 **지금 뚫려 있는 구멍을 막는 것이 아니라 대비**입니다. 호스팅을 옮기거나, Vercel이 IPv6를 지원하게 되거나, 로컬·자체 서버에서 띄울 때를 위한 것입니다.

## 왜 /64인가

IPv4 주소는 32비트라 한 사람이 쓸 수 있는 주소가 보통 하나(또는 공유기 뒤의 공인 IP 하나)입니다. IPv6는 128비트이고, 가정·회선 하나가 보통 **/64 대역**(앞 64비트가 같은 2⁶⁴개 주소)을 통째로 받습니다.

```
2001:db8:1:2:0000:0000:0000:0001
2001:db8:1:2:abcd:1234:5678:9abc      ← 전부 같은 사람(같은 회선)이 마음대로 쓸 수 있는 주소
2001:db8:1:2:ffff:ffff:ffff:ffff
└──── 앞 64비트 ────┘
```

주소 하나 단위로 세면, 시도마다 주소를 바꾸는 것만으로:

| 방어 | 우회되나 |
|---|---|
| IP 잠금(60초 5회 초과) / IP 단위 탐지 | ✅ 우회 — IP마다 1회씩 |
| 요청 제한(Flask-Limiter) | ✅ 우회 |
| 영구 IP 잠금(33단계) | ✅ 우회 |
| 계정 단위 잠금(24단계 회원, 38단계 관리자) | ❌ 계속 동작 — IP와 무관하게 아이디로 셈 |

## 바꾼 것 — 정규화는 한 곳에서

`ip_utils.normalize_ip()`를 만들고, 요청 IP를 얻는 유일한 함수인 `helpers.get_request_ip()`가 이 값을 돌려주게 했습니다.

| 접속 주소 | 이전 | 이후 |
|---|---|---|
| `203.0.113.10` (IPv4) | 그대로 | **그대로** |
| `2001:db8:1:2:abcd::5` (IPv6) | 그대로 | **`2001:db8:1:2::/64`** |
| `2001:DB8:1:2:0:0:0:A` (같은 대역, 다른 표기) | 그대로 | **`2001:db8:1:2::/64`** (같은 키) |
| `::ffff:203.0.113.10` (IPv4가 들어 있는 IPv6) | 그대로 | **`203.0.113.10`** |
| `::1` (루프백) | 그대로 | 그대로 — 로컬 개발 편의 |

`get_request_ip()`를 쓰는 곳(호출부 23곳)이 전부 자동으로 대역 단위가 됩니다 — 로그인 실패 집계, IP 잠금·영구 잠금, 요청 제한의 키, 보안 이벤트, 상관분석(27단계), IP 예외 출입증(34단계), 복구·재설정 요청의 IP 한도. 모두 `text` 칸이고 기존 데이터에 IPv6가 없어서 **마이그레이션이 필요 없습니다.** 대시보드에는 `2001:db8:1:2::/64`처럼 보이고, "즉시 해제"도 같은 키로 동작합니다.

대역 길이는 환경변수 **`IPV6_PREFIX_LENGTH`**(기본 64)로 바꿀 수 있습니다. 통신사에 따라 회선 하나에 /56이나 /48을 주기도 하기 때문입니다. 1~128 밖의 값은 64로 취급합니다.

## 함께 맞춘 곳

| 위치 | 바꾼 점 |
|---|---|
| `geoip.py` (위치 조회) | `x::/64`는 IP 형식이 아니라 그대로면 조회가 막힌다 → 대역이면 **대표 주소(`2001:db8:1:2::`)로 조회**. IP도 대역도 아니면 외부로 요청을 보내지 않는 SSRF 방지는 그대로(`ip_utils.lookup_address`) |
| `lockdown.is_ip_allowlisted()` | 요청 IP와 `.env`의 `PERMANENT_LOCK_IP_ALLOWLIST` 항목을 **둘 다 정규화해서 비교** — 관리자 PC의 IPv6 전체 주소를 적어도 같은 대역이면 인정 |
| `scripts/unlock_ip.py --ip` | IPv6 전체 주소를 넣어도 대역 키로 바꿔서 해제 |
| `X-Forwarded-For`(데모 전용 `TRUST_FORWARDED_FOR=true`) | 헤더의 IPv6도 똑같이 정규화. 형식이 이상하면 버리고 접속 주소로 되돌아가는 기존 규칙도 그대로 |

## 감수하는 점

- **같은 /64를 쓰는 사람들은 함께 잠깁니다**(한 집·한 사무실 정도). IPv4에서 공유기(NAT) 뒤 사람들이 함께 잠기는 것과 같은 성격이고, README의 "IP 단위 잠금" 제한사항과 같은 맥락입니다.
- 기록에도 **대역**이 남습니다(정확한 주소 대신). 탐지·잠금 단위와 기록 단위를 같게 두는 쪽을 택했습니다 — 정확한 주소까지 따로 남기려면 모든 표에 칸을 추가해야 해서 범위가 커집니다.
- 허용 목록에 `/48` 같은 넓은 대역을 적으면 설정 길이(/64)로 맞춰서 **그 대역의 첫 /64만** 인정됩니다. 허용 목록에는 관리자 PC의 주소(또는 /64)를 적어 주세요.

## 확인한 결과

자동 테스트 625개 → **650개**, 전부 통과 (`tests/test_ipv6_prefix.py` 25개 신규).

| 묶음 | 확인한 것 |
|---|---|
| 변환 규칙 | IPv4 그대로 / IPv6 → /64 / 표기가 달라도 같은 키 / IPv4가 들어 있는 IPv6 → IPv4 / 루프백 / 이미 대역 키여도 같은 결과 / 설정 길이(/56)·범위 밖 값 / IP가 아니면 그대로 |
| 실제 요청 | 접속 주소가 IPv6면 대역 키 / `X-Forwarded-For`의 IPv6도 정규화, 이상한 값은 접속 주소로 되돌아감 |
| 합산 | 같은 /64의 서로 다른 주소 2개의 로그인 실패가 **같은 키**로 기록, 다른 /64는 따로 |
| 요청 제한 | 같은 /64에서 주소를 바꿔도 11번째는 **429**, 다른 /64는 200 |
| 맞물림 | 허용 목록의 전체 IPv6 주소가 대역과 일치 / 위치 조회는 대표 주소로, 이상한 값은 요청 안 보냄 / 해제 스크립트가 전체 주소를 대역 키로 |

실제 IPv6 접속은 운영(Vercel)에 IPv6 입구가 없어 재현할 수 없어서, 테스트 클라이언트의 접속 주소(`REMOTE_ADDR`)를 IPv6로 바꿔 확인했습니다.
