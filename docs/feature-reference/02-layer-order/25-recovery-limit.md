# 25. 복구 요청 한도 + 처리 시간 기록

<aside>
🎯 **한 줄 요약**
복구 요청과 비밀번호 찾기는 가입 여부가 시간으로 새지 않게 **항상 일정한 시간(5초) 뒤에** 응답합니다. 그동안 서버 함수 하나가 묶여 있으므로 **요청 한도를 걸어 오래 붙잡지 못하게** 하고, **실제 처리 시간을 기록**해서 그 "5초"가 합리적인지 점검할 수 있게 했습니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [25-recovery-limit.html](25-recovery-limit.html)
> 📚 **계층**: Layer 5-B. 확장 기능 — Layer 5(방어 강화) + 공용 도구

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 민원 창구가 **항상 5초 걸려서** 처리 결과를 알려줌 (빨리 끝나도 5초) | 고정 응답 시간 |
| 한 사람이 창구에 **계속 줄을 서서 창구 직원을 붙잡음** | 한 IP가 요청을 쏟아부어 함수를 묶어 둠 |
| 한 사람당 **분당 5번까지만** 번호표 발급 | 복구 요청 한도 (분당 5회) |
| 실제로 **몇 초 걸렸는지 일지**에 적어 둠 | `[timing]` 로그 |

---

## ⚠️ 어떤 문제가 있었나요?

1. 복구 요청은 **고정 시간(처음 8초)** 동안 서버리스 함수 하나를 **붙잡고** 있습니다.
2. `/recovery/request`에는 **화면 단위 한도가 없어서** IP 하나가 분당 120번(전역 한도) 함수를 묶어 둘 수 있었습니다.
3. 고정 시간 **8초**도 **실측 근거가 없었습니다.**

---

## 🔧 고친 내용

| 변경 | 내용 |
|---|---|
| **복구 요청 한도** | IP당 **분당 5회**. 넘기면 **고정 대기 없이 바로 429** |
| **처리 시간 로그** | `[timing] /recovery/request work=0.61s target=5.0s` — 아이디·IP는 남기지 않음. 고정 시간을 넘기면 `overrun` 표시 |
| **고정 시간 8초 → 5초** | 운영 실측(메일 발송 3.04초)을 근거로 조정 |

<aside>
🧯 **한도를 넘긴 요청은 "기다리지 않고" 바로 끝납니다.**
한도에 걸린 요청까지 5초씩 붙잡아 두면 한도의 의미가 없습니다. 한도 검사는 **뷰 함수가 실행되기 전에** 일어나 즉시 429로 거절합니다. 이 거절은 `HTTP_FLOOD`(HIGH)로 기록됩니다(8단원).
</aside>

---

## 🔄 동작 순서

```
POST /recovery/request
   │
   ├─ IP당 분당 5회 초과 → 뷰 실행 전에 429 (HTTP_FLOOD 이벤트)
   ▼
run_with_fixed_response_time(work, started)
   ├─ work() 실행 (DB 조회 + 메일 발송)
   ├─ "[timing] /recovery/request work=0.61s target=5.0s" 기록
   └─ 남은 시간만큼 기다렸다가 응답
```

---

## 🧪 예시로 보기 (운영, 고정 8초 시절 측정)

| 요청 | 응답 | 실제 처리 |
|---|---|---|
| 비밀번호 찾기 — **실제 메일 발송** | 8.24초 | **3.04초** |
| 메일 없음 (없는 아이디 등) | 8.2~8.5초 | 0.81~1.47초 |
| `/recovery/request` **6번째** | **429**, 1.74초 | 실행 안 됨 |

→ 가장 느린 경우(메일 발송)도 3초대였으므로 8초는 과했고 5초로 줄였습니다.

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 복구·이메일 확인·비밀번호 찾기 한도 | `app.py` | `limiter.limit(...)` |
| 한도 초과 처리·기록 | `app.py` | `handle_rate_limit_exceeded()` |
| 고정 응답 시간 | `helpers/timing.py` | `run_with_fixed_response_time()` |
| 처리 시간 로그 | `helpers/timing.py` | `_log_timing()` |
| 설정 | `config.py` | `RECOVERY_REQUEST_RATE_LIMIT_PER_MINUTE`, `RECOVERY_MIN_RESPONSE_SECONDS` |

## 📖 용어 사전

<details>
<summary><b>overrun</b></summary>

처리가 고정 시간보다 **오래 걸렸다**는 표시입니다. 이러면 그 요청만 응답이 늦어져 계정 존재 여부가 드러날 수 있습니다.
</details>

<details>
<summary><b>429 Too Many Requests</b></summary>

"요청이 너무 많습니다"를 뜻하는 HTTP 상태 코드입니다.
</details>

## ⚠️ 알아둘 한계
