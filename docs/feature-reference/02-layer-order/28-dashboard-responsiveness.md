# 28. 대시보드 즉시 반응

<aside>
🎯 **한 줄 요약**
관리자 대시보드에서 버튼을 누르면 **2초 넘게 아무 반응이 없었습니다**(운영 측정 평균 2.22초). 이제 **누르는 순간 화면이 먼저 반응**하고, **필요한 표 하나만** 서버에 다시 받습니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [28-dashboard-responsiveness.html](28-dashboard-responsiveness.html)
> 📚 **계층**: Layer 5-B. 확장 기능 — Layer 4(관리) 화면의 브라우저(JS) + 서버

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 엘리베이터 버튼을 눌렀는데 **불이 안 들어오면** 다시 누르게 됨 | 응답 전에 화면 변화가 없어 같은 버튼을 또 누름 |
| 버튼을 누르면 **불이 바로 들어옴** | 누르는 즉시 "처리 중…" 표시 |
| 책 한 쪽을 넘기려고 **책 전체를 다시 인쇄**하지 않음 | 표 하나만 다시 받기 |

---

## ⚠️ 어떤 문제가 있었나요?

- "다음 페이지" 하나를 눌러도 **대시보드 전체**(표 8개 + 카드 6개, **DB 조회 약 21번**)를 다시 받았습니다.
- 응답이 오기 전에는 화면 변화가 없어 **같은 버튼을 다시 눌렀습니다.**

---

## ⚡ 개선 내용

| 개선 | 효과 |
|---|---|
| 페이지 버튼을 누르면 **응답을 기다리지 않고 번호를 바로 바꾸고** 표를 흐리게 | 3ms 만에 "2 / 8" + "불러오는 중…" |
| **그 표 하나만** 요청: `/api/status?only=<표 이름>` | DB 조회 **약 21번 → 1~2번** |
| 처리 버튼(해제·삭제·처리 완료·승인 등 **17종**)은 누르는 즉시 **"처리 중…"** | **두 번 눌리지 않음** |
| 전체 갱신은 조회 17개를 **한 번에** 보내고, 만료 잠금 정리는 **15초에 한 번만** | 12단원 |
| **늦게 도착한 옛 응답**이 방금 넘긴 페이지를 되돌려 놓지 않음 | |

---

## 🔄 1) "다음 페이지" 누를 때

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 번호를 **먼저 바꾼다** | 1과 마지막 페이지 사이로만 움직임. 표는 흐리게 |
| ② | **그 표 하나만** 서버에 요청 | 표 이름과 쪽 번호만 보냄 |
| ③ | 서버: 그 표의 **이번 쪽 + 전체 쪽 수**만 응답 | 모르는 표 이름은 **400** |
| ④ | **늦게 도착한 옛 응답은 버림** | 표마다 "가장 최근 요청 번호"를 기억해 마지막 요청의 응답만 그림 |
| ⑤ | 응답이 오면 **그 표만** 다시 그림 | 그사이 항목이 줄어 지금 쪽이 없어졌다면 마지막 쪽으로 다시 받음 |

<aside>
🧮 **"이전" 버튼을 6번 연타하면?**
번호는 **즉시 "1 / 8"** 로 바뀌고(음수나 0으로 내려가지 않음), 요청은 **1번만** 나갑니다. 예전에는 응답 전에 연타하면 "-4 / 8"처럼 보이기도 했습니다.
</aside>

### 페이지가 있는 표 8개
`attempts`(로그인 시도) · `users`(회원) · `posts`(게시글) · `comments`(댓글) · `admin_log`(관리자 로그인 기록) · `security_events`(보안 이벤트) · `security_incidents`(연관 사건) · `access_requests`(AI 조기 경보)

## 🔘 2) 처리 버튼 ("즉시 해제" 등)

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| 클릭 | 이미 처리 중인 버튼이면 **아무것도 안 함** | 더블 클릭 방지 |
| ① | 요청을 보내는 **순간** "처리 중…" | 확인 팝업을 **취소하면** 버튼은 바뀌지 않음 |
| ② | 서버에 처리 요청 | 로그인 세션 쿠키는 자동으로 가지만, **"이 화면에서 온 요청"** 임을 보이려고 서버가 준 **CSRF 토큰**도 함께 보냄 |
| ③ | 끝나면 **전체 갱신** + 버튼 복구 | 다음 폴링을 기다리지 않고 카드가 **바로 사라짐** |
| 서버 | 만료된 잠금 정리는 **15초에 한 번만** | 동시에 들어온 갱신 둘이 함께 정리하지 않게 잠금으로 보호 |

---

## 🧪 예시로 보기

| 확인 | 결과 |
|---|---|
| "다음" 클릭 직후 | **3ms** 만에 "2 / 8" + "불러오는 중…" |
| "이전" **6번 연타** (2페이지에서) | 즉시 "1 / 8", **요청 1번** |
| "즉시 해제" **3번 연타** | `/api/unlock` 요청 **1번** |
