# 27. 보이지 않는 탭은 폴링하지 않음

<aside>
🎯 **한 줄 요약**
화면이 **보이지 않을 때는 서버에 계속 묻지 않습니다.** 관리자 대시보드를 켜 둔 채 다른 탭에서 일하면 **분당 약 250번씩** DB를 왕복하던 낭비를 없애고, **탭으로 돌아오면 즉시 한 번 갱신**합니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [27-visible-tab-polling.html](27-visible-tab-polling.html)
> 📚 **계층**: Layer 5-B. 확장 기능 — Layer 4(관리) 화면의 브라우저 쪽(JS)

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 아무도 안 보는 **전광판**이 계속 새 소식을 받아오는 건 낭비 | 안 보이는 탭의 폴링 |
| 사람이 **전광판 앞으로 돌아오면 바로 최신 내용** 표시 | 탭이 보이면 즉시 갱신 |
| 답이 **오기도 전에 또 물어보면** 질문이 쌓여 서버가 더 느려짐 | `setInterval`로 요청이 겹침 |

<aside>
💡 **왜 필요했나요?**
관리자 대시보드는 5초마다 `/api/status`를 부르고, 한 번에 **DB 조회가 약 21번** 일어납니다. 그런데 탭이 안 보여도 계속 불러서, 탭을 켜 둔 채 다른 일을 하면 **분당 약 250번**씩 DB를 왕복했습니다. 또 `setInterval`은 이전 요청이 끝났는지 보지 않아, 서버가 느리면 **요청이 겹쳐 쌓였습니다.**
</aside>

---

## 🔧 공용 폴링 부품이 하는 일

관리자 대시보드와 게시글 화면(새 댓글 배너, 3단원)이 **같은 부품** `polling.js`를 씁니다.

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | **시작** | 바로 한 번 실행하거나, 한 주기 뒤에 첫 실행을 예약 |
| ② | 응답을 받은 **"뒤에"** 다음 요청을 예약 | `setTimeout`을 이어 붙이는 방식 → **진행 중인 요청은 항상 하나** |
| ③ | **탭이 숨겨져 있으면 예약하지 않음** | 다른 탭으로 이동·창 최소화 |
| ④ | 탭이 숨겨지면 **멈추고**, 다시 보이면 **즉시 한 번 갱신** | 자리를 비운 사이의 변화를 바로 보여줌 |
| ⑤ | 실패해도 **폴링은 멈추지 않음** | 일시적인 네트워크 오류 한 번으로 화면이 영영 멈추면 안 됨 |
| 서버 | 만료된 잠금 정리 3종을 **동시에** | IP·회원 계정·관리자 계정 (28단원에서 한 번 더 줄임) |

```
setInterval (예전)          setTimeout 연쇄 (지금)
요청 ──요청 ──요청 ──         요청 → 응답 → (5초) → 요청 → 응답 → ...
 느리면 겹쳐서 쌓임            항상 하나만 진행
```

## 🧪 예시로 보기

| 상황 | 이전 | 이후 |
|---|---|---|
| 다른 탭에 가 있음 | 분당 약 **250번** 조회 | **0번** |
| 탭으로 돌아옴 | 최대 5초 늦게 갱신 | **즉시** 갱신 |

## 🖥️ 직접 해보기

- [ ] 게시글 화면을 열고 개발자 도구 **Network 탭**에서 `/comments/latest` 호출을 지켜본다
- [ ] 다른 탭으로 갔다가 돌아온다 → 숨긴 동안에는 **호출이 없고**, 돌아오면 **바로 한 번** 호출되는지 확인

| 하는 일 | 파일 | 함수 |
