## 🔌 어댑터의 두 가지 일

### 1) 화면(HTML) 요청 — "껍데기"만 내려준다
브라우저가 주소를 **직접 열면** Next가 만든 정적 HTML을 그대로 내려줍니다. 이 요청은 껍데기일 뿐이라 **DB 조회·잠금 판정을 하지 않고**, 반복 접근 관찰 훅에도 잡히지 않습니다.

### 2) 데이터 요청 — 기존 라우트를 JSON으로
껍데기가 뜬 뒤 화면이 **같은 주소를 "어댑터 헤더"와 함께 다시 요청**합니다. 그러면 기존 라우트가 **평소처럼**(로그인 확인·권한 확인·요청 기록 포함) 실행되고, 결과가 JSON 봉투로 바뀌어 옵니다.

| 기존 라우트가 한 일 | JSON 봉투 |
|---|---|
| `render_template(...)` | `{"page": 템플릿 이름, "data": 넘긴 값}` |
| `redirect(...)` | `{"redirect": "/경로"}` |
| `flash(...)` | `"messages"` 배열 |
| 오류 응답 (429 등) | `{"messages": [...], "status": 코드}` |
| JSON 응답 (`/api/*`) | **손대지 않음** |

모든 응답에는 다음 POST에 쓸 **CSRF 토큰**(`csrf`)이 들어 있습니다.

## 🔄 흐름 순서

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 정적 HTML **껍데기**를 내려줌 | DB 조회·잠금 판정 없음 |
| ② | 인라인 스크립트만 **CSP 해시로 허용** | `'unsafe-inline'`으로 풀면 XSS 방어가 사라지므로, **우리가 빌드한 스크립트 내용만** 해시로 허용 |
| ③ | 화면이 같은 주소를 **어댑터 헤더**와 함께 다시 요청 | 이 헤더는 다른 사이트가 보낼 수 없어 CSRF 토큰과 별개의 **보조 방어선** |
| ④ | **기존 라우트가 평소대로** 실행 | 보안 로직 변경 없음 |
| ⑤ | **비밀 칸 제거** | `password`·`hash`·`token`·`secret`·`session_version`이 들어간 칸은 JSON으로 나가기 전에 지움 |
| ⑥ | **JSON 봉투**로 변환해 응답 | `{page, data, messages, csrf, redirect?}` |

<aside>
🔒 **비밀 칸을 지우는 이유**
템플릿은 서버 안에서만 그려져서 `user` 딕셔너리를 통째로 넘겨도 괜찮았지만, **JSON은 그대로 브라우저로 나갑니다.** 그래서 이름에 비밀을 암시하는 글자가 들어간 칸은 내보내기 전에 지웁니다.
</aside>

<aside>
🔗 **화면 이동은 일반 주소 이동만 씁니다 (`next/link` 사용 안 함)**
정적 내보내기의 클라이언트 이동은 `/login.txt` 같은 **조각 파일**을 요청하는데, Flask가 이를 **404로 기록해 "웹 스캐닝"(6단원)으로 오탐**합니다. 그래서 항상 `<a>`나 `window.location`으로 이동합니다.
</aside>

## 📊 관제 화면 숫자 — `GET /api/stats`

차트·히트맵·표의 숫자는 목록 전체가 아니라 **집계만** 내려받습니다. **새 표도 마이그레이션도 없이** 기존 표에서 계산합니다.

| 순서 | 동작 |
|:-:|---|
| ① | 잠금 목록 4개를 **동시에** 조회 (활성 잠금 수 계산) |
| ② | 집계를 계산 — 같은 집계를 여러 탭이 동시에 요청해도 **DB 조회는 한 번만**(짧게 보관) |
| ③ | 보안 이벤트·실패 로그인·404·미인증·사건·일별 요약·오늘 건수를 **동시에** 가져옴 |
| ④ | **순수 계산** — 시간대별 건수·7일 로그량·공격자 히트맵·신규/반복 공격자·국가별 흐름·미처리 이벤트 정렬 |

<aside>
🧪 **계산부를 DB와 분리한 이유**
순수 계산 함수(`build_threat_stats`)는 DB를 전혀 건드리지 않아서 **DB 없이도 테스트**할 수 있습니다. "L3/L4 공격"은 아직 수집하지 않아 화면에 "수집 전" 빈 상태로 보입니다.
</aside>

## 📖 용어 사전

<details>
<summary><b>어댑터(Adapter)</b></summary>

서로 맞지 않는 두 부분을 **이어주는 얇은 중간층**입니다. 여기서는 "화면(JSON을 원함)"과 "기존 라우트(HTML을 만듦)" 사이를 잇습니다.
</details>

<details>
<summary><b>정적 빌드(Static export)</b></summary>

서버가 요청마다 화면을 그리지 않고, **미리 만들어 둔 HTML·JS 파일**을 그대로 내려주는 방식입니다.
</details>

<details>
<summary><b>CSP 해시</b></summary>

"이 **정확한 내용**의 스크립트만 실행해도 된다"고 허용하는 지문입니다. 내용이 한 글자만 바뀌어도 해시가 달라져 막힙니다.
</details>
