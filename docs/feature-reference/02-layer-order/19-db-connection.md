# 19. 배포 환경 DB 연결 안정화

<aside>
🎯 **한 줄 요약**
배포 사이트(Vercel)에서 `/login`·관리자 대시보드가 **가끔 500 오류**를 냈습니다. 원인은 **쉬던 DB 연결이 이미 닫혀 있었는데 그걸 그대로 쓴 것**이었고, **연결을 만드는 한 곳만 고쳐서** 해결했습니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [19-db-connection.html](19-db-connection.html)
> 📚 **계층**: Layer 5-A. 확장 기능 — 모든 계층 **아래**의 데이터 접근 계층(`db` 패키지)입니다

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 한참 **쓰지 않던 전화선**은 상대가 이미 끊어 놓았는데, 모르고 말을 걸었다가 "연결이 끊겼습니다" | 쉬던 연결을 재사용하다 `Server disconnected` |
| 전화를 걸기 전에 **"아직 연결돼 있나?" 확인**하고, 끊겼으면 새로 건다 | HTTP/1.1 + 쉬는 연결 5초 제한 |
| **듣기만 하는 질문**은 한 번 더 물어봐도 괜찮지만, **송금**은 두 번 하면 큰일 | 조회(GET)만 재시도, 기록·수정은 재시도 안 함 |

<aside>
💡 **왜 서버리스에서 특히 문제였나요?**
서버리스 함수는 요청이 없으면 **잠시 "잠들고"**, 요청이 오면 다시 깨어납니다. 잠든 사이 Supabase가 연결을 닫아도 함수는 그 사실을 모르고, 깨어나서 **닫힌 연결로** 요청을 보내 실패했습니다. 다시 요청하면 정상이라 더 헷갈렸습니다.
</aside>

---

## 🔧 고친 내용 (연결 설정 3가지)

| 설정 | 하는 일 |
|---|---|
| ① **HTTP/1.1** | 연결을 여러 개 두고, 쉬던 연결을 **다시 쓰기 전에 닫혔는지 확인**해서 닫혔으면 새로 맺음 |
| ② **5초 넘게 쉰 연결은 재사용 안 함** + **접속 단계 실패는 1회 재시도** | 아직 아무것도 보내지 않은 상태라 재시도해도 안전 |
| ③ **조회(GET/HEAD)만**, 연결이 끊겨 실패하면 **1회 재시도** | 기록·수정(POST/PATCH/DELETE)은 **재시도하지 않음** |

<aside>
🚫 **기록·수정은 왜 재시도하지 않나요?**
서버에는 **이미 반영됐는데 응답만 끊긴** 경우가 있습니다. 이때 다시 보내면 **두 번 기록**됩니다. 로그인 실패 기록이 두 번 남으면 **잠금 횟수가 틀어지는** 식의 문제가 생깁니다.
</aside>

---

## 🔄 동작 순서

| 순서 | 동작 |
|:-:|---|
| 시작 | 어떤 `db` 함수든 `db.get_client()`를 부름 — **처음 한 번만** 실제 연결을 만들고 이후 재사용 |
| ① | 연결 설정을 직접 만들어 Supabase 클라이언트에 넘김 |
| ② | HTTP/1.1 · 쉬는 연결 5초 · 접속 1회 재시도 |
| ③ | 이후 모든 DB 요청이 **재시도 전송 계층**을 통과 — 조회가 연결 끊김으로 실패하면 새 연결로 1회 재시도 |

<aside>
🏗️ **구조가 도와준 점**
이 프로젝트는 **`db` 패키지만 DB와 대화**합니다. 그래서 DB 호출 **155곳을 하나도 안 바꾸고** 연결을 만드는 **한 곳만** 바꿔서 해결할 수 있었습니다. "DB 접근을 한 곳에 모은다"는 구조의 장점입니다.
</aside>

## 🖥️ 확인 방법

로컬에서는 재현하기 어렵습니다. 배포 후 Vercel 런타임 로그(무료 플랜은 1시간 보관)에서 `RemoteProtocolError`가 없는지 확인합니다.

## 📖 용어 사전

<details>
<summary><b>HTTP/2 vs HTTP/1.1</b></summary>

HTTP/2는 연결 **하나**로 여러 요청을 보내고, HTTP/1.1은 연결을 **여러 개** 둡니다. 여기서는 **끊긴 연결을 감지하기 쉬운** HTTP/1.1을 택했습니다.
</details>

<details>
<summary><b>서버리스(Serverless)</b></summary>

서버를 계속 켜 두지 않고, 요청이 올 때만 함수가 깨어나 실행되는 방식입니다. 요청이 없으면 함수는 멈춰 있습니다.
</details>
