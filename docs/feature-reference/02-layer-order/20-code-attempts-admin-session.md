## 🔢 1) 6자리 복구 코드 — 비교 "전에" 시도권 예약

6자리 코드는 경우의 수가 **100만 개뿐**이라, **시도 횟수 제한이 유일한 방어선**입니다.

| 방식 | 동시에 1000개를 보내면 |
|---|---|
| ❌ 예전: 비교 → 틀리면 +1 | 횟수가 오르기 **전에** 1000개가 전부 비교를 마침 |
| ✅ 지금: **시도권 예약** → 비교 | 시도권 5장 → **최대 5개만 비교**, 나머지는 거절 |

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 요청한 기기가 아니면 **공통 문구** | 시도권도 쓰지 않음 (22단원) |
| ② | **시도권 1회를 먼저 예약** | "읽은 횟수 그대로일 때만 +1" (조건부 UPDATE). 경쟁에서 지면 다시 읽고 재시도(최대 3번) |
| ③ | 예약 실패 → **맞는 코드여도 거절** | 실패 쪽으로 닫힘 |
| ④ | 이제서야 코드 비교 | 틀렸고 **마지막 기회**였다면 요청 취소 |
| 보조 | `/recovery/verify` 제출에 **분당 10회** 한도 | 2차 방어선 (서버 인스턴스마다 따로 셈) |

<aside>
🎯 **마지막 시도권으로 맞게 입력한 사용자는 성공해야 합니다.**
그래서 한도에 닿았다고 예약 단계에서 요청을 취소하지 않고, **마지막 시도마저 틀렸을 때만** 취소합니다.
</aside>

## 🛂 2) 관리자 세션 — 요청마다 DB 계정과 대조

세션 쿠키는 **서명만 되어 있고 서버가 따로 보관하지 않습니다.** 예전처럼 "아이디가 들어 있는가"만 보면 삭제된 관리자도 남은 쿠키로 계속 접근하고, 같은 아이디로 계정을 다시 만들면 **옛 쿠키가 되살아났습니다.**

로그인할 때 세션에 **3가지**를 넣습니다: 아이디 · **계정 기본키(`admin_id`)** · **로그인 시각**.

| 순서 | 확인 | 무효이면 |
|:-:|---|---|
| ① | 세션 값이 **모두** 있나? | 다시 로그인 (이 기능 이전의 옛 세션 포함) |
| ② | 로그인한 지 **8시간**이 지났나? | 다시 로그인 |
| ③ | DB에 그 **id의 계정이 지금도 있고, 아이디가 같나?** | 다시 로그인 (삭제·재생성되면 id가 달라 걸러짐) |
| 통과 | 계정(역할 포함)을 `g.admin`에 담고 라우트 실행 | |

<aside>
⏰ **수명은 "마지막 활동"이 아니라 "로그인 시각" 기준입니다.**
대시보드가 5초마다 폴링하므로 "활동이 없는 상태"가 생기지 않기 때문입니다.
</aside>

### "세션 없음"과 "무효 세션"을 구분합니다

| 상황 | 의미 | 처리 |
|---|---|---|
| **세션이 아예 없음** | 공격일 수 있음 | 401 + **미인증 접근 기록·탐지** (6단원) |
| **세션은 있는데 무효** | 다시 로그인해야 할 관리자 | **기록하지 않고** 관리자 세션만 지움 |

기록하면 삭제된 관리자의 대시보드가 5초마다 폴링하면서 **그 관리자 IP가 공격으로 오탐**되어 알림이 울립니다.

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 코드 제출 처리 | `routes/recovery.py` | `recovery_verify_submit()` |
| 시도권 예약 | `db/recovery.py` | `reserve_recovery_code_attempt()` |
| 요청 취소 | `db/recovery.py` | `revoke_recovery_request()` |
| 제출 분당 한도 | `app.py` | `limiter.limit(...)` |
| 관리자 세션 시작 | `helpers/auth.py` | `start_admin_session()` |
| 세션 검증 | `helpers/auth.py` | `_load_current_admin()` |
| 실패 응답 구분 | `helpers/auth.py` | `_reject_admin_request()` |

## 🖥️ 직접 해보기

- [ ] 관리자 A로 로그인한 채, 다른 브라우저의 super_admin이 "관리자 계정 관리" 카드에서 A를 삭제한다
- [ ] A의 대시보드가 **5초 안에** 로그인 화면으로 바뀌는지 확인한다

> 배포 직후 기존 관리자 세션에는 `admin_id`가 없어 **한 번 다시 로그인**해야 합니다.

## 📖 용어 사전

<details>
<summary><b>조건부 UPDATE</b></summary>

"이 값이 아직 **내가 읽은 값일 때만** 고쳐라"는 조건을 붙인 갱신입니다. Supabase REST에서는 트랜잭션을 쓸 수 없어 이 방식으로 동시 요청을 막습니다.
</details>

<details>
<summary><b>기본키(Primary key)</b></summary>

표의 각 줄을 구분하는 고유 번호입니다. 같은 아이디로 계정을 다시 만들어도 **기본키는 새로 부여**되므로 옛 세션과 구분됩니다.
</details>
