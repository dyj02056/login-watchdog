# 29. IPv6 /64 대역 단위 정규화

<aside>
🎯 **한 줄 요약**
IPv6 사용자는 보통 **/64 대역(2⁶⁴개 주소)** 을 통째로 받아서 **주소를 거의 공짜로 바꿀 수** 있습니다. 주소 하나 단위로 세면 시도마다 주소만 바꿔도 모든 방어가 무력화되므로, **IPv6는 "대역" 하나를 한 사람(한 단위)** 으로 봅니다.
</aside>

> 🗺️ **클릭해서 코드를 볼 수 있는 흐름도**: [29-ipv6-prefix.html](29-ipv6-prefix.html)
> 📚 **계층**: Layer 5-B. 확장 기능 — 공용 도구(`helpers/`)와 서비스(`services/`)

---

## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 아파트 **한 동 전체**를 한 가구가 쓰면서 **호수만 계속 바꿔** 출입 | IPv6 주소를 계속 바꾸는 공격자 |
| 출입 금지를 **"호수"가 아니라 "동"** 단위로 건다 | /64 **대역** 단위로 센다·잠근다 |
| IPv4는 **집 주소 하나가 곧 한 가구** | 그대로 사용 |

<aside>
⚠️ **왜 필요한가요?**
주소 하나를 단위로 세면 **시도마다 주소를 바꾸는 것만으로** IP 잠금 · IP 단위 탐지 · 요청 제한 · 영구 잠금이 **모두 무력화**됩니다. (이 단계는 지금 뚫린 구멍이 아니라, **호스팅을 바꾸거나 자체 서버를 운영할 때**에 대한 대비입니다.)
</aside>

---

## 🔑 변환 규칙

| 접속 주소 | 키 (탐지·잠금 단위) | 이유 |
|---|---|---|
| `203.0.113.10` | `203.0.113.10` | IPv4는 **그대로** |
| `2001:db8:1:2:abcd::5` | `2001:db8:1:2::/64` | IPv6는 **/64 대역** |
| `::ffff:203.0.113.10` | `203.0.113.10` | IPv4가 들어 있는 IPv6는 **IPv4로** (같은 사람이 두 표기로 접속해도 한 명으로) |
| `::1` | `::1` | **루프백**(내 컴퓨터)은 그대로 — 로컬 개발 편의 |

대역 길이는 `IPV6_PREFIX_LENGTH`(기본 **64**)로 바꿀 수 있습니다.

---

## 🔄 어떻게 적용되나요?

```
요청 도착
   │
   ▼
get_request_ip()      ← 요청 IP를 얻는 "유일한" 함수
   │   (데모 설정일 때만 X-Forwarded-For를 믿고, 진짜 IP 형식일 때만 사용)
   ▼
normalize_ip()        "2001:db8:1:2:abcd::5" → "2001:db8:1:2::/64"
   │
   ▼
탐지 · 잠금 · 요청 제한 · 보안 이벤트 · 상관분석 · IP 예외가 이 키로 동작
```

<aside>
🧰 **한 곳만 바꿔서 전부 바뀐 이유**
모든 탐지·잠금·요청 제한이 **`get_request_ip()` 한 곳의 값**을 쓰기 때문에, 이 함수만 바꿔서 전부 대역 단위가 되었습니다. "같은 일을 하는 코드를 한 곳에 모은다"는 구조의 장점입니다.
</aside>

### 같은 단위로 비교하는 곳들

| 곳 | 어떻게 |
|---|---|
| **허용 목록** (관리자 PC) | 양쪽을 **같은 단위로 정규화**해서 비교 — `.env`에 IPv6 전체 주소를 적어도 같은 대역이면 인정 |
| **위치 조회** | 대역 키(…/64)로는 외부 서비스에 못 물으므로 **대표(네트워크) 주소**로 조회. IP도 대역도 아니면 요청 자체를 안 보냄 |
| **요청 제한** (Flask-Limiter) | 키 함수로 `get_request_ip`를 그대로 사용 |

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 요청 IP 얻기 | `helpers/request_utils.py` | `get_request_ip()` |
| 정규화 | `services/ip_utils.py` | `normalize_ip()` |
| 위치 조회용 주소 | `services/ip_utils.py` | `lookup_address()` |
| 허용 목록 비교 | `security/lockdown.py` | `is_ip_allowlisted()` |

## 🖥️ 확인 방법

운영 배포 주소에는 IPv6 입구(AAAA 레코드)가 없어 **실제 IPv6 접속은 재현할 수 없습니다.** 대신 테스트 `tests/test_ipv6_prefix.py`가 테스트 클라이언트의 접속 주소를 IPv6로 바꿔 확인합니다. IPv6 접속이 있다면 기록·잠금 카드에 **대역 키**가 보입니다.

## 📖 용어 사전

<details>
<summary><b>/64</b></summary>

IPv6 주소 128비트 중 **앞 64비트가 같은** 주소 묶음입니다. 보통 가정·사무실이 이 묶음을 통째로 받습니다.
</details>

<details>
<summary><b>정규화(normalize)</b></summary>

같은 대상을 가리키는 여러 표기를 **하나의 표준 형태**로 맞추는 일입니다.
</details>

## ⚠️ 알아둘 한계

- 같은 /64를 쓰는 사람들(한 집·한 사무실 정도)은 **함께 잠깁니다.** IPv4에서 공유기 뒤의 사람들이 함께 잠기는 것과 같은 성격입니다.
