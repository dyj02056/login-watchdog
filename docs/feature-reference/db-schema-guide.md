# Supabase DB 스키마 가이드 (비전공자용)

이 문서는 [docs/schema.sql](schema.sql)에 정의된 Supabase 테이블 25개를 "이게 왜 있고, 어떤 값이 들어가는지" 비전공자도 알 수 있게 정리한 문서입니다.

> 실제 스키마 정의(SQL)는 [docs/schema.sql](schema.sql)이 원본입니다. 이 문서는 그걸 읽기 쉽게 풀어 쓴 참고 자료이며, 스키마가 바뀌면 이 문서도 함께 업데이트해야 합니다.

## 한눈에 보는 전체 목록

테이블은 성격에 따라 크게 3가지로 나뉩니다.

| 분류 | 의미 | 해당 테이블 |
|---|---|---|
| **자산 / 콘텐츠** | 앱이 다루는 "진짜 데이터" (사람이 직접 만든 것) | `users`, `admin_users`, `posts`, `comments`, `roles`, `permissions`, `app_settings` |
| **과거 기록 (로그)** | "언제 무슨 일이 있었는지" 계속 쌓이기만 하는 표 | `login_attempts`, `admin_login_log`, `signup_attempts`, `post_attempts`, `comment_attempts`, `not_found_attempts`, `unauthorized_attempts`, `page_access_attempts`, `api_access_log`, `lock_history` |
| **현재 상태 / 판정 결과** | "지금 이 순간 어떤 상태인지"를 나타내는 표 | `lockouts`, `account_lockouts`, `security_events`, `security_incidents`, `access_requests`, `recovery_requests`, `ip_lock_exemptions`, `ip_locations`(캐시) |

**로그와 상태 표의 차이가 헷갈릴 수 있는데**, 예를 들어 `login_attempts`(로그)는 "10시에 실패, 10시 1분에 실패, 10시 2분에 성공"처럼 있었던 일을 전부 쌓아두는 표이고, `lockouts`(상태)는 "지금 이 IP가 잠겨있다/아니다"라는 딱 하나의 결론만 담아두는 표입니다.

---

## 1. `users` — 감시 대상 로그인에 가입하는 일반 회원

이 프로젝트가 실제로 감시하는 `/login` 화면에 로그인하기 위해 가입하는 "일반 사용자" 계정입니다. 관리자(`admin_users`)와는 완전히 별개입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 (자동 증가) | 회원마다 자동으로 매겨지는 고유 번호 |
| `username` | 글자 | 로그인 아이디. 다른 사람과 중복될 수 없음 |
| `email` | 글자 | 가입할 때 입력한 이메일. 역시 중복 불가 |
| `name` | 글자 | 화면에 보여줄 표시 이름. 가입 직후엔 빈 값이고, 나중에 프로필 수정에서 채움 |
| `password_hash` | 글자 | 비밀번호를 그대로 저장하지 않고 암호화(해시)한 값 — 원문 비밀번호는 DB 어디에도 없음 |
| `created_at` | 날짜/시각 | 가입한 시각 |

---

## 2. `login_attempts` — `/login` 시도 기록 (계속 쌓이는 로그)

누가 언제 어떤 IP에서 로그인에 성공/실패했는지 하나도 빠짐없이 쌓아두는 표입니다. 브루트포스(비밀번호 무차별 대입) 탐지의 핵심 재료입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 시도 기록 번호 |
| `ip_address` | 글자 | 시도한 사람의 IP 주소 |
| `username` | 글자 | 그때 입력한 아이디 (실제 가입 여부와 무관하게 입력값 그대로 저장) |
| `success` | 참/거짓 | 로그인 성공 여부 |
| `attempted_at` | 날짜/시각 | 시도한 시각 |

---

## 3. `lockouts` — IP 단위 잠금의 "현재 상태"

`login_attempts`가 "지나간 일들의 기록"이라면, 이 표는 "지금 이 순간 이 IP가 잠겨있는지"라는 결론만 담습니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `ip_address` | 글자 (기본키) | 잠긴 IP 주소 |
| `locked_at` | 날짜/시각 | 잠긴 시각 |
| `unlock_at` | 날짜/시각 (영구 잠금은 없음) | 자동으로 풀릴 예정 시각. 영구 잠금이면 비어 있다 |
| `failure_count` | 숫자 | 잠기게 된 원인이 된 실패 횟수 |
| `active` | 참/거짓 | 지금도 잠겨있는 상태인지 |
| `lock_type` | 글자 | `TEMPORARY`(5분 후 자동 해제) / `PERMANENT`(영구 — 이메일 인증이나 관리자 해제로만 풀림) |
| `recoverable` | 글자 | 영구 잠금을 어떻게 풀 수 있는지: `SELF`(이메일로 완전 해제) / `EXEMPTION`(이메일로 "본인+본인 기기 예외"만 발급) / `ADMIN_ONLY`(관리자만) |
| `permanent_reason` | 글자 (없을 수 있음) | 영구로 올라간 이유 (`REPEAT_OFFENDER`, `SIEM_CRITICAL`, `SIEM_HIGH`, `ADMIN_MANUAL` 등) |
| `promoted_at` | 날짜/시각 (없을 수 있음) | 영구 잠금으로 올라간 시각 |

---

## 4. `account_lockouts` — 계정 단위 잠금의 "현재 상태"

공격자가 여러 IP로 나눠서(또는 아주 천천히) 같은 계정 하나만 노리면, IP별로는 실패 횟수가 기준을 안 넘어서 `lockouts`로는 못 잡습니다. 이 표는 IP와 상관없이 "이 계정이 총 몇 번 실패당했는지"를 기준으로 따로 잠급니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `username` | 글자 (기본키) | 잠긴 계정의 아이디 |
| `locked_at` | 날짜/시각 | 잠긴 시각 |
| `unlock_at` | 날짜/시각 | 자동으로 풀릴 예정 시각 |
| `failure_count` | 숫자 | 잠기게 된 총 실패 횟수 (여러 IP 합산) |
| `active` | 참/거짓 | 지금도 잠겨있는지 |

---

## 5. `admin_users` — 관리자 계정

대시보드에 로그인해서 보안 이벤트를 확인하고 조치하는 "관리자" 계정입니다. 서버가 처음 켜질 때 `.env` 설정값으로 1명이 자동 생성되고, 회원가입 화면 자체가 없습니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 관리자 고유 번호 |
| `username` | 글자 | 관리자 로그인 아이디 |
| `password_hash` | 글자 | 암호화된 비밀번호 |
| `role` | 글자 | 권한 등급 — `security_viewer`(조회만) / `security_admin`(조치 가능) / `super_admin`(전체 권한) 중 하나 |
| `created_at` | 날짜/시각 | 계정 생성 시각 |

---

## 6. `admin_login_log` — 관리자 로그인 감사 기록

관리자가 `/admin/login`에 로그인을 시도한 성공/실패 이력입니다. 관리자 화면 자체의 감사 로그입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 기록 번호 |
| `username` | 글자 | 시도한 관리자 아이디 |
| `success` | 참/거짓 | 성공/실패 |
| `ip_address` | 글자 | 시도한 IP |
| `attempted_at` | 날짜/시각 | 시도 시각 |

---

## 7. `app_settings` — 서버 전체가 공유하는 설정값

지금은 딱 하나의 설정("회원가입 켜짐/꺼짐")만 있고, 항상 1개 행만 존재하도록 강제되어 있습니다. 서버 메모리가 아니라 DB에 저장하는 이유는, 여러 서버 인스턴스가 동시에 떠 있어도 다들 같은 값을 보게 하기 위해서입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 (항상 1) | 설정 행이 딱 하나만 있도록 고정하는 값 |
| `signup_enabled` | 참/거짓 | 지금 회원가입을 받을지 여부 |

---

## 8. `ip_locations` — IP 위치 조회 결과 캐시

IP로 국가/도시를 알아내주는 외부 서비스(`ip-api.com`)는 분당 45번까지만 무료로 물어볼 수 있습니다. 한 번 조회한 결과는 여기 저장해두고, 다음에 같은 IP가 나오면 외부에 다시 안 물어보고 이 표에서 바로 꺼내 씁니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `ip_address` | 글자 (기본키) | 조회한 IP |
| `country` | 글자 (없을 수 있음) | 국가 |
| `region_name` | 글자 (없을 수 있음) | 지역 |
| `city` | 글자 (없을 수 있음) | 도시 |
| `lookup_failed` | 참/거짓 | 이 IP는 조회가 실패했었는지 (예: 사설 IP `127.0.0.1`) |
| `looked_up_at` | 날짜/시각 | 조회한 시각 |

---

| 컬럼 | 값 종류 | 설명 |

| `ip_address` | 글자 | 시도한 IP |
| `attempted_at` | 날짜/시각 | 시도 시각 |

## 14. `not_found_attempts` — 존재하지 않는 경로(404) 요청 기록

공격자가 이곳저곳 없는 페이지 주소를 찔러보는 "Web Scanning" 행위를 탐지하기 위한 로그입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 기록 번호 |
| `ip_address` | 글자 | 요청한 IP |
| `path` | 글자 | 어떤(존재하지 않는) 경로를 요청했는지 |
| `attempted_at` | 날짜/시각 | 요청 시각 |

## 15. `unauthorized_attempts` — 권한 없는 접근 시도 기록

`not_found_attempts`와 비슷하지만, "아예 없는 경로"가 아니라 "존재는 하는데 로그인/권한이 없어서 막힌 경로"에 접근한 경우를 기록합니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 기록 번호 |
| `ip_address` | 글자 | 요청한 IP |
| `path` | 글자 | 권한 없이 접근하려 한 경로 |
| `attempted_at` | 날짜/시각 | 요청 시각 |

| `id` | 숫자 | 기록 번호 |

| `path` | 글자 | 반복 요청된 페이지 경로 |
| `attempted_at` | 날짜/시각 | 요청 시각 |

## 17. `security_events` — 통합 보안 이벤트 (관리자 대시보드의 핵심 표)

관리자 대시보드에서 보게 되는 "보안 이벤트 목록"이 바로 이 표입니다. 위에서 소개한 여러 로그 표들을 분석한 "결론"(이벤트)들이 여기에 모입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 이벤트 번호 |
| `event_type` | 글자 | 어떤 종류의 이벤트인지 (예: `BRUTE_FORCE`, `BOT_DETECTED`, `WEB_SCANNING` 등) |
| `severity` | 글자 | 위험 등급 — `MEDIUM` / `HIGH` / `CRITICAL` |
| `ip_address` | 글자 | 관련된 IP |
| `path` | 글자 (없을 수 있음) | 관련된 경로 (경로와 무관한 이벤트는 비어있음) |
| `count` | 숫자 | 이 이벤트가 지금까지 몇 번 반복됐는지 |
| `action` | 글자 | 자동으로 취한 조치 (예: `LOCK_IP`, `REJECTED`) |
| `username` | 글자 (없을 수 있음) | 계정 단위 이벤트일 때만 채워짐 |
| `detected_at` | 날짜/시각 | 처음 탐지된 시각 |
| `resolved_at` | 날짜/시각 (없을 수 있음) | 처리 완료된 시각. 비어있으면 아직 "미해결" 상태 |

---

## 18. `security_incidents` — 여러 이벤트를 하나로 묶은 "사건철"

`security_events`가 이벤트 하나하나의 개별 신고서라면, 이 표는 "같은 IP가 짧은 시간 안에 서로 다른 종류의 수상한 행동을 2개 이상 저질렀을 때" 그 신고들을 하나의 사건으로 묶어주는 표입니다(SIEM 상관분석).

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 사건 번호 |
| `ip_address` | 글자 | 관련 IP |
| `event_types` | 글자 목록 | 이 사건에 묶인 이벤트 종류들 (예: `["WEB_SCANNING", "BRUTE_FORCE"]`) |
| `severity_max` | 글자 | 묶인 이벤트 중 가장 위험한 등급 |
| `status` | 글자 | `OPEN`(진행 중) / `IDLE`(활동 없음 — 마지막 이벤트로부터 30분 넘게 조용해 새 사건이 따로 열렸지만 아직 관리자 미해결) / `CLOSED`(관리자가 해결) |
| `first_event_at` | 날짜/시각 | 사건에 묶인 첫 이벤트 시각 |
| `last_event_at` | 날짜/시각 | 가장 최근 이벤트 시각 |
| `escalated` | 참/거짓 | "복합 공격 발생" 알림을 이미 한 번 보냈는지 (중복 알림 방지용 표시) |
| `resolved_at` | 날짜/시각 (없을 수 있음) | 관리자가 "해결"을 누른 시각. 예전에 잠금 해제로 자동 종료된 사건은 비어 있음 |
| `resolved_by` | 글자 (없을 수 있음) | "해결"을 누른 관리자 아이디 (로그인 세션 기준) |

---

## 19. `roles` — 관리자 역할 목록

관리자가 가질 수 있는 권한 등급 3종을 정의해두는 아주 작은 표입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `role` | 글자 (기본키) | `security_viewer`(조회 전용) / `security_admin`(조치 가능) / `super_admin`(전체 권한) |

## 20. `permissions` — 역할별로 할 수 있는 조치 목록

어떤 역할(role)이 어떤 조치(action)를 할 수 있는지 한 줄씩 나열해둔 표입니다. 관리자가 버튼을 누를 때마다 이 표를 확인해서 "이 역할이 이 조치를 해도 되는지" 판단합니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `role` | 글자 | 조치를 할 수 있는 역할 (`roles` 표와 연결) |
| `action` | 글자 | 허용된 조치 (예: `unlock_ip`, `delete_user`, `manage_admin_users`, `approve_pending_action`, `resolve_incident` 등) |

## 21. `api_access_log` — `/api/*` 요청 전체 기록 (매크로/봇 탐지용)

같은 IP가 짧은 시간에 서로 다른 API 여러 개를 옮겨 다니며 호출하는 "매크로/봇처럼 보이는 패턴"을 잡기 위한 로그입니다. GET뿐 아니라 POST 등 모든 방식의 요청을 기록합니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 기록 번호 |
| `ip_address` | 글자 | 요청한 IP |
| `path` | 글자 | 요청한 API 경로 |
| `method` | 글자 | 요청 방식 (`GET`, `POST` 등) |
| `requested_at` | 날짜/시각 | 요청 시각 |

## 22. `access_requests` — LLM이 미리 알려주는 "조기 경보" 승인 대기함

지금까지의 탐지 방식은 전부 "정해진 기준(임계값)을 넘었을 때"만 반응합니다. 이 표는 그 반대로, 아직 기준을 넘지는 않았지만 AI(LLM)가 "이건 지켜볼 필요가 있어 보인다"고 판단한 건들을 관리자가 검토해서 승인/반려할 수 있게 대기시켜두는 표입니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `request_id` | 숫자 | 요청 번호 |
| `event_type` | 글자 | 어떤 유형의 조기 경보인지 (`BRUTE_FORCE`, `WEB_SCANNING` 등) |
| `pending_action` | 글자 | 승인되면 실제로 실행할 조치 (`LOCK_IP` / `LOCK_ACCOUNT` / `ALERT_ONLY`) |
| `target_kind` | 글자 | 대상이 IP인지 계정인지 (`ip` / `account`) |
| `target_value` | 글자 | 대상이 되는 IP 주소 또는 계정 아이디 |
| `path` | 글자 (없을 수 있음) | 관련 경로 (해당하는 유형만) |
| `count` | 숫자 | 지금까지의 시도/발생 횟수 |
| `threshold` | 숫자 | 원래 이 유형이 자동 조치되는 기준값 |
| `context_count` | 숫자 (없을 수 있음) | 부가 참고 수치 (예: 관련된 서로 다른 아이디/IP 개수) |
| `context_ip` | 글자 (없을 수 있음) | 계정 잠금을 승인할 때 필요한 "이번 시도를 유발한 IP" |
| `llm_reason` | 글자 | AI가 이걸 위험하다고 판단한 이유 설명 |
| `status` | 글자 | `PENDING`(대기 중) / `APPROVED`(승인됨) / `REJECTED`(반려됨) |
| `requested_at` | 날짜/시각 | 경보가 생성된 시각 |
| `decided_by_admin_id` | 숫자 (없을 수 있음) | 승인/반려를 처리한 관리자 |
| `decided_at` | 날짜/시각 (없을 수 있음) | 승인/반려 처리 시각 |

## 23. `lock_history` — 잠금이 걸린 이력 (영구 잠금 판단의 근거)

`lockouts`/`account_lockouts`는 같은 IP·계정이 다시 잠기면 같은 줄을 덮어쓰기 때문에 "최근 30일 안에 몇 번 잠겼나"를 셀 수 없습니다. 이 표는 잠금이 걸릴 때마다 **한 줄씩 추가만** 해서 그 횟수를 셉니다. (줄을 고치거나 지우지 않는 "append-only" 표입니다.)

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 이력 번호 |
| `target_kind` / `target_value` | 글자 | 대상이 IP인지 계정인지(`ip`/`account`)와 그 값 |
| `lock_type` | 글자 | `TEMPORARY` / `PERMANENT` |
| `trigger_reason` | 글자 | `THRESHOLD`(임계값 초과) / `REPEAT_OFFENDER`(반복 위반) / `SIEM_CRITICAL` / `SIEM_HIGH` / `NETWORK_IDS` / `ADMIN_MANUAL` |
| `source_event_type` | 글자 (없을 수 있음) | 어떤 공격 유형 때문에 잠겼는지 (`BRUTE_FORCE`, `ADMIN_BRUTE_FORCE` 등) |
| `incident_id` | 숫자 (없을 수 있음) | 연결된 연관 사건 |
| `trigger_note` | 글자 (없을 수 있음) | 관리자 수동 승격 사유 |
| `locked_at` | 날짜/시각 | 잠긴 시각 |
| `released_at` / `released_by` / `release_note` | (없을 수 있음) | 풀린 시각, 푼 주체(`EMAIL_RECOVERY`, `admin:<아이디>`, `script:<이름>`), 해제 사유 |

## 24. `recovery_requests` — 이메일로 보낸 1회용 복구 링크/코드

영구 잠금된 사용자가 `/recovery`에서 본인 인증을 요청하면 한 줄이 생깁니다. 토큰(링크)과 6자리 코드는 **원문이 아니라 해시(지문)만** 저장해서, DB가 유출돼도 진짜 링크는 알 수 없습니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 요청 번호 |
| `user_id` | 숫자 | 복구를 요청한 회원 (회원이 삭제되면 함께 삭제) |
| `target_kind` / `target_value` | 글자 | 풀려는 대상 — 계정(`account`) 또는 요청한 IP(`ip`) |
| `token_hash` | 글자 | 메일 링크 토큰의 SHA-256 해시 (중복 불가) |
| `code_hash` | 글자 | 6자리 코드의 SHA-256 해시 |
| `device_hash` | 글자 (없을 수 있음) | 요청한 기기 쿠키(`lw_dev`)의 해시 — IP 복구는 이 기기에서만 완료 가능 |
| `requested_ip` | 글자 | 요청한 IP |
| `status` | 글자 | `PENDING`(대기) → `VERIFIED`(완료) / `EXPIRED`(만료) / `REVOKED`(취소·코드 5회 실패) |
| `code_attempts` | 숫자 | 6자리 코드를 틀린 횟수 |
| `expires_at` / `created_at` / `verified_at` | 날짜/시각 | 만료·요청·완료 시각 (유효시간 15분) |

같은 (회원, 대상)에 `PENDING`은 동시에 1건만 존재할 수 있습니다(부분 유니크 인덱스).

## 25. `ip_lock_exemptions` — IP 영구 잠금의 "본인 + 본인 기기" 출입증

IP가 영구 잠금되어도, 이메일 인증을 마친 **그 회원이 그 기기로** 접속하는 경우만 통과시키는 표입니다. 같은 와이파이(NAT)를 쓰는 공격자가 피해자의 아이디를 알아도, 기기 쿠키가 없으면 계속 막힙니다.

| 컬럼 | 값 종류 | 설명 |
|---|---|---|
| `id` | 숫자 | 예외 번호 |
| `ip_address` | 글자 | 예외가 적용되는 IP |
| `user_id` | 숫자 | 예외를 받은 회원 |
| `device_hash` | 글자 | 예외를 받은 기기 쿠키의 해시 |
| `granted_via` | 글자 | `EMAIL_RECOVERY` / `ADMIN` |
| `status` | 글자 | `ACTIVE` → `REVOKED`(관리자 회수·연속 로그인 실패) / `EXPIRED` |
| `granted_at` / `expires_at` | 날짜/시각 | 발급·만료 시각 (기본 30일) |
| `revoked_reason` | 글자 (없을 수 있음) | 회수 사유 |

---

## 용어가 낯설다면

- **참/거짓(boolean)**: "예/아니오"만 담는 값. 예를 들어 `active`가 참이면 "지금 잠겨있다", 거짓이면 "잠겨있지 않다".
- **null(비어있음)**: 그 칸에 해당 사항이 없어서 값이 아예 안 들어간 상태. "0"이나 "빈 글자"와는 다릅니다.
- **기본키(Primary Key)**: 그 표에서 각 줄을 서로 구별해주는 "고유한 값" — 같은 값이 두 번 나올 수 없습니다.
- **해시(hash)**: 원래 값을 알아볼 수 없게 암호화한 값. 비밀번호를 그대로 저장하지 않고 해시로 저장하면, DB가 유출되어도 실제 비밀번호는 알 수 없습니다.
- **캐시(cache)**: 나중에 또 쓸 걸 대비해서 미리 계산/조회한 결과를 저장해두는 것 — 매번 새로 조회하는 수고를 덜어줍니다.
