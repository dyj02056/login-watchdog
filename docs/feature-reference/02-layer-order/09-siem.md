## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 낱개의 신고들 (소음 민원, 수상한 사람 목격…) | `security_events` (개별 이벤트) |
| 형사가 "같은 사람의 소행이네" 하고 **사건 파일**로 묶음 | `security_incidents` (사건) |
| 사건 종결은 **담당자가 확인하고 도장** | 관리자 "해결" 버튼 |

<aside>
💡 **SIEM이란?** Security Information and Event Management. 여러 곳의 보안 이벤트를 모아 **상관관계를 분석하는** 보안 업계의 표준 개념입니다.
</aside>

## 🔄 사건이 만들어지는 순서

이벤트가 하나 기록될 때마다(8단원) 자동으로 실행됩니다.

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 최근 5분 안에 **서로 다른 유형**이 몇 개? | 같은 IP의 최근 이벤트 유형을 중복 없이 가져옴 |
| ② | **2개 미만**이면 끝 | 단발성 이벤트까지 사건으로 만들면 사건 표가 이벤트 표와 같아져서 |
| ③ | 사건 열기 / 갱신 | 열린 사건이 있으면 **병합**, 없으면 **새로 열기** |
| ④ | 오래 조용했던 사건 처리 | 마지막 이벤트로부터 **30분 넘게** 조용했으면 `IDLE`(활동 없음)로 옮기고 새 사건을 연다 |
| ⑤ | 병합 규칙 | 유형 목록은 **합집합**, 위험등급은 **더 높은 쪽** |
| ⑥ | 에스컬레이션 판단 | 사건이 충분히 심각한지 확인 (10단원) |

<aside>
🔔 **왜 오래 조용한 사건은 병합하지 않나요?**
옛 사건이 이미 "알림 발송 완료(escalated)" 상태로 남아 있으면, 그 IP의 **새 공격이 옛 사건에 합쳐지면서 알림이 조용히 사라질** 수 있습니다. 옛 사건을 IDLE로 옮기고 **새 사건**을 열면 새 공격에 대해 알림이 다시 나갑니다.
</aside>

## ✅ 사건은 "관리자 버튼"으로만 닫힙니다

| 구분 | 의미 |
|---|---|
| **IP 잠금 해제** | 접속 **차단을 거두는** 조치 (사건은 그대로) |
| **사건 해결** | 관리자가 내용을 확인하고 **조사가 끝났다**는 판단 (사건이 `CLOSED`) |

- 누가(`resolved_by`) 언제(`resolved_at`) 해결했는지 기록됩니다.
- 해결자 이름은 **요청 본문이 아니라 로그인 세션**에서 가져옵니다. 본문 값은 위조할 수 있기 때문입니다.
- 이미 해결된 사건을 다시 눌러도 안전합니다(OPEN/IDLE만 대상).

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 사건으로 묶을지 판단 | `security/correlate.py` | `check_and_correlate()` |
| 최근 유형 목록 | `db/incidents.py` | `get_recent_distinct_event_types()` |
| 사건 열기·병합·IDLE | `db/incidents.py` | `record_incident()`, `_merge_into_existing()`, `mark_incident_idle()` |
| 사건 해결 | `db/incidents.py` / `routes/admin/incidents.py` | `resolve_incident()` / `api_security_incidents_resolve()` |
| 시간 창 설정 | `config.py` | `INCIDENT_CORRELATION_WINDOW_MINUTES`(5분), `INCIDENT_MERGE_IDLE_MINUTES`(30분) |

## 🧪 예시로 보기

IP `1.2.3.4`가 **5분 안에** 404를 11번 유발(`WEB_SCANNING`) → 곧이어 같은 IP로 로그인 실패 6회(`BRUTE_FORCE`)
→ 서로 다른 유형 2개 → `security_incidents`에 사건 1건 생성, `event_types: ["WEB_SCANNING", "BRUTE_FORCE"]`

## 🖥️ 직접 해보기

- [ ] 위 순서(웹 스캐닝 먼저, 브루트포스 나중)를 5분 이내에 재현한다
- [ ] 관리자 대시보드 "연관 사건" 표에서 두 유형이 함께 묶인 사건 1건을 확인한다
- [ ] IP 잠금을 해제해도 사건 상태가 **진행 중** 그대로인지 확인한다
- [ ] "처리" 열의 **"해결"** 버튼을 눌러 `해결됨`으로 바뀌고 해결자·시각이 표시되는지 확인한다

## 📖 용어 사전

<details>
<summary><b>병합(merge)</b></summary>

새 이벤트를 새 사건으로 만들지 않고, 이미 열려 있는 사건에 합치는 것입니다. 한 IP에는 열린(OPEN) 사건이 **하나만** 존재하도록 DB가 보장합니다.
</details>

<details>
<summary><b>OPEN / IDLE / CLOSED</b></summary>

진행 중 / 활동 없음(관리자는 아직 미해결) / 해결됨.
</details>

## ⚠️ 알아둘 한계

- 5분이라는 창은 고정 설정이라, **하루에 걸친 저속 공격**은 하나의 사건으로 묶이지 않습니다.
- `OPEN → IDLE` 전환은 **새 이벤트가 들어올 때만** 일어납니다(별도 타이머 없음). 새 이벤트가 없는 사건은 30분이 지나도 "진행 중"으로 남습니다. 관리자가 주기적으로 확인해 닫아야 합니다.
