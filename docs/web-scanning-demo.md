# Web Scanning 탐지 재현

프로젝트 루트에서 본인 소유 또는 테스트 허가를 받은 서버를 대상으로 실행한다.
Python 표준 라이브러리만 사용하므로 이 스크립트 자체는 패키지 설치와 로그인이 필요 없다.

```powershell
py scripts/web_scanning_sim.py --host http://127.0.0.1:5000
```

`--host`를 테스트 서버 주소로 바꿀 수 있다. 경로를 제외한 기본 URL을 입력한다.
프로그램은 `/admin.php/__scan_<실행ID>`, `/.env/__scan_<실행ID>`,
`/wp-login.php/__scan_<실행ID>` 등 흔한 스캐너 타깃 문자열에 임의의 실행 ID를
붙인 서로 다른 경로를 무작위 순서로 요청한다. 이렇게 기존 경로와의 충돌을 줄이지만,
서버의 포괄 라우팅이나 프록시 설정에 따라 404가 아닌 응답이 올 수도 있다.
정상 완료 시 GET은 정확히 11회이며, 리다이렉트 추적·자동 재시도·사전 확인 요청은 없다.
통신 오류 시 요청 도달 여부를 알 수 없으므로 즉시 중단한다.

## 재현 전제

- 서버 설정이 `WEB_SCANNING_ALERT_THRESHOLD=10`이어야 한다.
- 같은 IP에서 기본 `DETECTION_WINDOW_SECONDS=60`초 안에 404가 11회 기록되어야 한다.
- 실행 전 해당 IP의 기존 404 기록이 시간창에서 빠지도록 60초보다 길게 기다리고,
  실행 중 같은 IP의 다른 테스트 요청을 멈춘다. 임계값을 이미 넘었다면 알림이 다시
  발생하지 않을 수 있고, 기존 기록이 있으면 이번 실행의 11번째보다 먼저 발생할 수 있다.
- 프록시/WAF가 직접 만든 404는 Flask 탐지기에 도달하지 않을 수 있다.
- 서버 시간창을 변경했다면 `--window`도 맞춘다. 이 옵션은 서버 설정을 변경하지 않는다.

## 성공 확인

응답은 11번째에도 404다. 이 탐지는 IP를 잠그지 않으므로 HTTP 응답만으로
탐지 성공을 판정할 수 없다. 스크립트 종료 코드 0은 **404 11회 및 소요 시간 조건 충족**을
뜻하며, 알림이나 DB 기록까지 확인했다는 뜻은 아니다. 종료 코드 1은 통신 오류 또는
재현 조건 미충족, 2는 잘못된 CLI 인자다.

1. Slack 메시지에서 `[MEDIUM]`과 `Web Scanning 의심`을 확인한다.
   `SLACK_WEBHOOK_URL`이 비어 있으면 같은 메시지가 서버 콘솔에 출력된다.
   현재 코드에는 `[MEDIUM] WEB_SCANNING`이라는 연속된 문자열이 출력되지 않는다.
2. `/admin/login`에서 관리자로 로그인한 뒤 `/admin/dashboard`의 보안 이벤트 표를
   확인하거나, 같은 브라우저 세션에서 `/api/status` 응답의 `security_events`를 확인한다.
   스캔 요청에는 로그인이 불필요하지만 이벤트 조회에는 관리자 로그인이 필요하다.
3. 새 이벤트의 `event_type=WEB_SCANNING`, `severity=MEDIUM`, `count=11`,
   `action=ALERTED`와 접속 IP·발생 시각을 확인한다. `path`에는 프로그램이 출력한
   실행 ID가 포함된 경로가 있어야 한다. 이벤트가 많으면 API의
   `security_events_page` 파라미터로 다음 페이지를 확인한다.

알림은 요청을 기록한 다음 `detector.is_web_scanning(ip)`의 count가 정확히 11일 때
`soar.notify_web_scanning()`에서 전송하고 보안 이벤트를 저장한다.
