## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 동네 커뮤니티 게시판 | `/board` |
| 게시판은 주민만 출입 | 회원 문지기 (`member_login_required`) |
| 내 게시물만 떼어낼 수 있음 | 본인 글·댓글만 수정·삭제 |

| "새 글이 올라왔어요" 알림판 | 새 댓글 알림 배너 |

## ✍️ 1) 글쓰기가 일어나는 순서

글을 쓸 때도 회원가입처럼 **검문이 먼저**입니다.

| 순서 | 검문 | 쉬운 설명 | 막히면 |
|:-:|---|---|---|
| ① | 사람이 맞나? | 숨은 입력칸(허니팟)이 채워져 있으면 봇으로 보고 기록도 남기지 않고 거부 | "일시적인 오류가 발생했습니다." |
| ② | 너무 자주 쓰나? | 같은 IP가 **1분 안에 5번 이상** 시도하면 거부하고 사실을 기록 | "너무 많은 게시글 작성 시도가 감지되었습니다." |
| ③ | 이번 시도 기록 | 성공·실패와 상관없이 시도를 한 줄 남김 (②의 횟수가 여기서 쌓임) | – |
| ④ | 제목·내용 검사 | 빈칸 없는지, 제목 100자·내용 5000자 이하인지 | 안내 문구 |
| ⑤ | 저장 → 상세 화면 | 저장 후 방금 쓴 글로 이동 (다시 방문 방식) | – |

<aside>
🧾 **왜 "판정 → 기록" 순서일까요?**
먼저 "이미 너무 많이 시도했나?"를 보고, 그다음 이번 시도를 기록합니다. **막힌 시도도 기록**되어야 계속 두드리는 사람이 계속 막히기 때문입니다. 회원가입(1단원)도 같은 순서입니다.
</aside>

---

## 🛠️ 2) 수정 · 삭제는 본인 글만

| 동작 | 서버가 하는 확인 |
|---|---|
| 수정 폼 열기 | 글이 있나? → **내 글인가?** (아니면 폼 자체를 안 보여줌) |
| 수정 저장 | 위 확인을 **다시 한 번** + 봇·도배 검사(글쓰기와 횟수 공유) + 길이 검사 |
| 삭제 | 내 글일 때만 삭제. 딸린 댓글도 DB 규칙으로 **자동 삭제** |

<aside>
🛡️ **버튼을 숨기는 것만으로는 안전하지 않아요.**
화면에서 "수정" 버튼을 숨겨도, 개발자 도구로 요청을 직접 만들어 보낼 수 있습니다. 그래서 **서버가 제출 때 한 번 더** 소유권을 확인합니다(이중 검증).
</aside>

---

## 💬 3) 댓글

글쓰기와 같은 순서(봇 확인 → 도배 판정 → 시도 기록 → 길이 검사 → 저장)를 따릅니다.

- 정상적인 대화에서는 댓글이 더 자주 달리므로 기준치가 더 넉넉합니다(**1분 10회**).
- 댓글 삭제는 **내 댓글**일 때만 됩니다.
- 처리가 끝나면 항상 글 상세 화면으로 돌아갑니다(다시 방문 방식).

---

## 🔔 4) 새 댓글 알림 배너

내가 글을 보고 있는 동안 누가 댓글을 달면 **"새로운 댓글이 추가되었습니다"** 배너가 뜹니다.

```
브라우저 ──(5초마다)──▶ "이 글 댓글이 몇 개고, 마지막은 언제야?"
서버     ──────────────▶ { 개수: 3, 최신시각: ... }   ← 이 두 값만!
브라우저: 처음 본 값과 다르면 → 배너 표시 → 누르면 새로고침
```

<aside>
🪶 **가볍게 만든 이유**
댓글 내용 전체가 아니라 **개수와 최신 시각**만 주고받기 때문에 5초마다 확인해도 서버 부담이 적습니다. 그리고 탭이 보이지 않을 때는 확인을 **멈춥니다**(27단원).
</aside>

## 🧪 예시로 보기

- 회원 A가 60초 안에 글쓰기를 **6번째** 시도 → 거부 + "너무 많은 게시글 작성 시도가 감지되었습니다" 안내, 동시에 HIGH 위험등급 이벤트(`POST_RATE_LIMIT`)가 기록됩니다.
- 회원 B가 회원 A의 글 수정 주소로 직접 요청 → "본인이 작성한 글만 수정할 수 있습니다."

## 📖 용어 사전

<details>
<summary><b>Post-Redirect-Get</b></summary>

폼 제출을 처리한 뒤 같은 화면을 바로 그리지 않고, "해당 주소를 다시 방문"시키는 방식입니다. 새로고침해도 폼이 중복 제출되지 않습니다.
</details>

<details>
<summary><b>폴링(polling)</b></summary>

일정한 간격으로 "바뀐 게 있나요?" 하고 계속 물어보는 방식입니다. 이 프로젝트는 5초마다, 탭이 보일 때만 물어봅니다.
</details>

<details>
<summary><b>cascade(연쇄 삭제)</b></summary>

부모(글)를 지우면 딸린 자식(댓글)도 DB가 알아서 함께 지워주는 규칙입니다.
</details>
