## 🏢 비유로 먼저 이해하기

| 현실 | 이 프로젝트 |
|---|---|
| 아파트 입주민 전용 공간 | 회원 대시보드 (`/dashboard`) |
| 공동현관 경비원 | **회원 문지기** (`member_login_required`) |
| 내 우편함 | 내 로그인 기록 (`/dashboard/history`) |
| 신분 재확인 (큰 변경 전) | 이메일·비밀번호 변경 시 "현재 비밀번호" 요구 |

<aside>
💡 **왜 필요한가요?** 회원이 "내 계정이 언제, 어디서 로그인 시도됐나"를 직접 볼 수 있어야 낯선 곳에서의 시도(도용 의심)를 스스로 알아챌 수 있습니다.
</aside>

## 🚪 1) 첫 화면과 문지기

회원 화면은 **전부 문지기가 먼저 지킵니다.** 문지기는 두 가지를 확인합니다.

| 순서 | 확인 | 쉬운 설명 | 통과 못 하면 |
|:-:|---|---|---|
| ① | 로그인했나? | 세션에 아이디가 있는지 봅니다. | 로그인 화면으로 이동 |
| ② | 세션이 아직 유효한가? | 세션에 적힌 **세대 번호**가 DB 값과 같은지 봅니다. 다른 기기에서 비밀번호를 바꿨거나 계정이 삭제되면 번호가 달라져 세션이 끊깁니다. | "비밀번호가 변경되었거나 계정 정보가 바뀌어 로그아웃되었습니다." |
| ③ | 내 정보 읽기 | 세션의 회원 번호로 내 행을 가져옵니다. 그 사이 계정이 사라졌다면 세션을 정리합니다. | "계정 정보를 찾을 수 없습니다." |
| ④ | 화면 그리기 | **표시 이름**이 있으면 그 이름으로, 없으면 로그인 아이디로 인사합니다. 이메일이 미인증이면 안내 배너도 보여줍니다. | – |

<aside>
🪪 **세션 세대 번호란?** 출입증에 찍힌 "발급 차수" 같은 것입니다. 비밀번호를 바꾸면 차수가 올라가서, 이전 차수의 출입증(다른 기기의 로그인)은 모두 무효가 됩니다.
</aside>

## 📜 2) 내 로그인 기록 (`/dashboard/history`)

| 순서 | 동작 | 쉬운 설명 |
|:-:|---|---|
| ① | 내 아이디로만 조회 | 내 아이디로 **처음부터 내 기록 20건만** DB에 물어봅니다. |
| ② | 접속 위치 붙이기 | 각 기록의 IP를 "South Korea · Seoul" 같은 문장으로 바꿔 붙입니다(4단원). |
| ③ | 화면에 표시 | 표로 보여줍니다. |

<aside>
🔒 **더 안전한 설계 포인트**
"전체 기록을 가져온 뒤 화면에서 남의 것을 숨기는" 방식이 아니라, **애초에 내 것만 물어보는** 방식입니다. 실수로 화면 처리가 틀려도 남의 기록이 서버 밖으로 나올 길이 없습니다.
</aside>

## ✏️ 3) 프로필 · 이메일 · 비밀번호

| 변경 | 확인 절차 | 결과 |
|---|---|---|
| 표시 이름 | 별도 확인 없음 | 바로 저장하고 프로필 화면을 **다시 방문(redirect)** |
| 이메일 | 현재 비밀번호 + 새 주소로 **확인 링크** | 링크를 눌러야 실제로 바뀌고, 바뀌면 **기존 주소로 알림** (23단원) |
| 비밀번호 | 현재 비밀번호 + 새 비밀번호 규칙 | 저장 + **다른 기기 로그인 모두 해제** + 알림 메일 (18단원) |

<aside>
🛡️ **왜 이메일·비밀번호는 현재 비밀번호를 또 묻나요?**
세션(로그인 상태)만 훔친 사람이 이메일을 자기 주소로 바꿔 계정을 가로채는 일을 막기 위해서입니다. 그리고 여기서 현재 비밀번호를 **틀리면 로그인 실패와 똑같이 기록·잠금**됩니다. 그렇지 않으면 이 화면이 "잠금 없이 비밀번호를 무한히 맞춰보는 뒷문"이 되기 때문입니다.
</aside>

<details>
<summary>🔁 <b>Post-Redirect-Get 패턴이 뭔가요?</b></summary>

폼을 제출해서 처리한 뒤 같은 화면을 바로 그리면, 사용자가 새로고침할 때 **같은 폼이 또 제출**됩니다. 그래서 처리 후에는 `redirect`로 "해당 주소를 다시 방문"시켜서 새로고침해도 안전하게 만듭니다.
</details>

## 📍 코드는 어디에 있나요?

| 하는 일 | 파일 | 함수 |
|---|---|---|
| 회원 문지기 | `helpers/auth.py` | `member_login_required()`, `clear_member_session()` |
| 첫 화면 | `routes/member.py` | `member_dashboard()` |
| 내 로그인 기록 | `routes/member.py` | `member_history()` |
| 프로필 · 이메일 · 비밀번호 | `routes/member.py` | `member_profile_submit()`, `member_email_change_submit()`, `member_password_submit()` |
| 기록에 위치 붙이기 | `helpers/request_utils.py` | `_attach_locations()` |
| 회원 조회·수정 | `db/users.py` | `get_user_by_id()`, `update_user_name()`, `update_user_password()` |
| 내 시도 기록 조회 | `db/attempts.py` | `list_attempts_by_username()` |

## 🧪 예시로 보기

- 표시 이름을 한 번도 안 바꾼 신규 회원 → 인사말에 **로그인 아이디**가 그대로 표시됩니다.
- 프로필에서 표시 이름을 "홍길동"으로 바꾸면 → 다음 방문부터 인사말이 **"홍길동"** 으로 바뀝니다.
- 다른 기기에서 비밀번호를 바꾸면 → 이 기기에서 아무 화면이나 열 때 "로그아웃되었습니다" 안내와 함께 로그인 화면으로 이동합니다.

## 🖥️ 직접 해보기

- [ ] 회원가입 후 로그인 → `/dashboard`에서 인사말을 확인한다
- [ ] `/dashboard/profile`에서 표시 이름을 바꾼다 → 대시보드 인사말이 바뀌었는지 확인한다
- [ ] 로그인 실패를 한 번 일으킨 뒤 `/dashboard/history`에서 그 시도가 기록되는지 확인한다
- [ ] 브라우저 두 개로 로그인한 뒤, 한쪽에서 비밀번호를 바꾸면 다른 쪽이 로그아웃되는지 확인한다

## 📖 용어 사전

<details>
<summary><b>문지기(데코레이터)</b></summary>

함수 위에 붙이는 `@member_login_required` 표시입니다. "이 화면 함수를 실행하기 전에 먼저 이 검사를 거쳐라"는 뜻입니다.
</details>

<details>
<summary><b>세션 세대 번호(session_version)</b></summary>

회원마다 DB에 저장된 번호입니다. 로그인할 때 세션에 같은 번호를 적어두고, 요청마다 DB 번호와 비교합니다. 비밀번호를 바꾸면 DB 번호만 올라가서 오래된 세션이 자동으로 무효가 됩니다.
</details>

## ⚠️ 알아둘 한계

- 위치 조회는 공인 IP 기준이라, 내 컴퓨터에서 직접 테스트할 때(127.0.0.1)는 "위치 확인 불가"로 표시됩니다.
